# What the rewards model stands for

`models/Rewards.tla` checks one promise in two parts: an earned reward is banked at most once, and it is never lost, through crashes, failed saves, two game processes on one profile and a run file that an older build left. This page names the code behind every variable and action. Line numbers are at the sync commit at the end of this page.

Run it the same way as the run-flow model: `bash models/make-rewards-configs.sh` writes every `rewards-*.cfg`, and each config runs through `pstack`'s `statechart` skill or plain TLC. A config with two game processes checks one rule and has millions of states, so run it with plain TLC and several workers: `java -XX:+UseParallelGC -cp <tla2tools jar> tlc2.TLC -workers 4 -config rewards-<name>.cfg Rewards.tla`. The reach configs hold several probes; run each probe on its own (TLC stops at the first break, and `-continue` crashed TLC 1.7.4 on `rewards-reach`).

## The rules

| Rule         | The promise                                                     | How it is stated                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------ | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AtMostOnce` | No reward id is granted twice.                                  | `landed <= 1`: no two successful profile saves each write a grant of the id that their own process made.                                                                                                                                                                                                                                                                                                                                                                                                         |
| `NeverLost`  | An earned and settled id is granted after any crash and reload. | Never reach `Lost`: the profile file (`user://profile.json`) holds the targeted key or the legacy key settled without the unlock, and no running game holds the unlock in memory. From that state no code grants it: every load and every take-in copies the file, the profile merge keeps settled ids (a union), every grant refuses a settled targeted key (`sketches/core-loop/src/core/progress.gd:128`, `:225`), and the legacy branch counts a profile's legacy key with no targeted key as paid (`:125`). |
| `LockInCall` | The save lock is held only inside a call.                       | A process that holds `lk` has steps left in its queue.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

`NeverLost` is an invariant, not a rule about time. It names the state from which the grant can never come, so it holds exactly when the eventual promise does under the code's grant guards.

## Not modelled

The `.prev` run copy (`keep_prev`, `restore_prev`) and its restore; a profile file that cannot be read or comes from a newer build (both stop all profile saves for the session: covered as failed writes, not as their own state); the profile backup on a schema upgrade; the ledger leaves (`ledger.found.*`, where the settle is itself the grant, so a run-document settle without a profile save loses nothing); W50 WorkOrders and Maker Licenses (`_complete_work_order` -> `profile.transact(_complete_work_order_now)` using `order:*` and `license:*` keys, which `reconcile_settled` skips beside `reward:*` at `sketches/core-loop/src/core/progress.gd:210`); a row's reward target changing after the earn; more than one reward id; a run's merge of an older in-memory run document on load (`sketches/core-loop/src/core/run_store.gd:77`).

The save lock is modelled as perfect. Not modelled: a game that waits longer than `LOCK_WAIT_MS` (250 ms) for it and then runs the change on memory and fails its saves, and every lock for the rest of that transact fails at once (`sketches/core-loop/src/core/profile.gd:106-115`, `:96-99`, `:132-133`), which can pay twice and loses nothing; a stale lock broken while its holder still lives (a game stopped for over 5 s inside one save); two games breaking one stale lock at once; and an older build saving beside this one, which takes no lock.

Not repaired and not modelled (finding R-1): builds from 4 October to 16 November could leave the profile holding a reward key settled without its unlock. The model starts from a profile that never held one, and such a reward stays unpaid; the repair (re-apply a reward that is settled but not owned) is card W1-121, a ruling ea call.

Known gaps in the save points:

- `EndRun` leaves out `_record_end`'s own profile saves before the tombstone: the ladder save on a win (`sketches/core-loop/src/core/flow.gd:1127`) and `_persist_companion` (`:1131`). A save that succeeds there writes the grant, so leaving them out only adds paths that lose; it hides no loss.
- `Checkpoint` writes the run's current settled list. `_on_death_saved` (`sketches/core-loop/src/core/flow.gd:555-562`) rewrites the stored `_entrance` document, which was built at the last entrance or cleared save and can predate an earn, so in the code that save may carry an older settled list than the model's. It can only drop a key from the run file, which makes a loss need a later save point; it adds no path.
- `_save_cleared` (`sketches/core-loop/src/core/flow.gd:1163-1168`) is folded into `Checkpoint` with the other `_save` callers.
