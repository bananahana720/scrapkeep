# Scrapkeep project instructions

Read [the project desk](docs/project/README.md) and [CONTRIBUTING.md](CONTRIBUTING.md) before substantive work. Personal A stack preferences and host policy still apply. The game is a Godot sketch at `sketches/core-loop` with three worlds. Since 10 Nov 2026 the alpha is coordinated from one local Claude Code session on Andrew's PC, which is also the Gate and runs GPU work there (ruling cs); the claude.ai project "Scrapkeep" coordinated from 23 Oct to 10 Nov, and the same rules apply to a session in either place. The live board is the current wave's GitHub board issue, named in [project-guide/handoff/STATE.md](project-guide/handoff/STATE.md) with the wave state; [project-guide/coord/GRAPH.md](project-guide/coord/GRAPH.md) is the wave 18 board, kept as history. The rulings are in [project-guide/handoff/DECISIONS.md](project-guide/handoff/DECISIONS.md) and the order of what is left in [project-guide/handoff/ROADMAP.md](project-guide/handoff/ROADMAP.md). Alpha work stacks on `stage/alpha-w<N>`. Andrew plays a world 1 sitting first, then one full-alpha sitting ("wave 21" in older records); no per-wave play asks.

- `BIBLE.md` and accepted `adr/` records own game and production direction. `BACKLOG.md` owns task definitions, `TRACKING.md` owns live execution and questions, and `ORCHESTRATOR.md` owns assignment, isolation, review and integration. Read the task's exact sources; a proposed sprint or ready card is not authorization to start it.
- Use `plan-session` for planning, `scrapkeep-task` for authorized cards, `scrapkeep-verify` for artifact-specific verification, `scrapkeep-lab` for the headless Godot lab, `scrapkeep-blockout` for mojulo blockout pieces and their ball proofs, and `reactive-model-loop` for a fast model that decides inside a running system. The skill bodies live under `.agents/skills/`, linked into `.claude/skills` (`reactive-model-loop` mirrors its canonical pstack copy); `.agents/skills/README.md` says when to add a skill, and `npm run check:skills` checks them.
- Preserve `/` and `/orchard.html` as separate browser proofs (preserved proofs, not the current direction) until consolidation is explicitly approved. Their tests do not qualify the future native game.
- Keep orchard combat state in `src/orchard/simulation.js`, rendering in `scene.js`, procedural models in `models.js`, and input/UI orchestration in `main.js`. Consult the lightning integration contract before changing interfaces. Damage and telegraphs consume the same committed geometry.
- Deep modules, simple interfaces (Andrew, 9 November 2026): in the game, put new behaviour inside the module that owns the state and give callers one small call, never a reach into private members; do not widen an interface to save a few lines. [DEEP-SWEEP.md](project-guide/handoff/DEEP-SWEEP.md) has the method.
- No slop in anything the player meets (ruling cx, Andrew, 10 November 2026): before a word goes on a screen, ask whether position, shape, colour, an icon, motion or sound should carry the fact instead. No eyebrow labels, no heading that restates the screen, no label that restates its value, one name for one thing, and no filler. Keep the game's voice. [LEGIBILITY.md](sketches/core-loop/design-v3/LEGIBILITY.md) section 13 has the pattern list and the carrier order; a change a player can read or navigate is written and reviewed against it.
- World 1 design directions (rulings ct, cu and cv, Andrew, 10 November 2026): every map is held to the ten-point map standard with a fast check per point, difficulty is tuned harder and never easier through movement, and a world plays as one ride with no hard cut between stages. Read the audit for the area in [project-guide/handoff/shared/world1/](project-guide/handoff/shared/world1/) before changing a map, the difficulty or a hand-over.
- Use locked dependencies and existing free local tools. Get Andrew's go-ahead first for a dependency upgrade, an engine migration, a paid service or a deployment, because each changes what he pays for or ships; a housekeeping task is not that go-ahead. Game features ride the light play lane.
- For completed browser-proof code changes, run `npm run verify` and the applicable browser checks in CONTRIBUTING. For documentation/configuration-only work, use scoped structure, link and behavioral checks; do not run builds under a no-build scope. Native checks come from the approved engineering handoff, not guessed commands. Godot sketches under `sketches/` follow ORCHESTRATOR's light play lane: `npm run sketch:smoke`, Andrew plays, playtest log, merge. The gate for alpha PRs and promotions (focused tests plus `npm run sketch:fast` per PR, the wave gate per promotion, the full release gate once per sprint) is ORCHESTRATOR's tiered gate; it is the only owner of that rule.
- One thread, one writer (ruling by, Andrew, 9 November 2026): a project thread writes its own changes, runs its own checks and owns its pull request from claim to merge. It starts a sub-agent only for work that writes nothing and returns a short finding: wide search, research, a long noisy run, and the independent review of its finished diff. Work too big for one thread goes to the coordinator to split into threads. ORCHESTRATOR owns the rule.
- One home for every fact (ruling bz, Andrew, 9 November 2026): update the existing page, doc or record before making a new one, link instead of repeating, and add anything new to the library in the same turn. [START-HERE.md](project-guide/handoff/START-HERE.md) has the "Where to go when" map.
- Writing agents use disjoint worktrees with verified base identity. The coordinator alone admits changes and writes canonical execution records. Follow ORCHESTRATOR's scoped prose-staging exception. Claude project agents are the only workers (the Codex lane retired on 17 October 2026). The definitions in `.claude/agents` own the pins, by tier and not by version (ruling bp, Andrew, 9 November 2026): the fast tier at medium for search, lookup and (in a local coordinator session, or as a whole thread) well-specified mechanical writing, the mid tier at medium for routine review, the acceptance gate and work that only runs and compares tests, and the top tier at high for judgement and consequential review. The pins are family aliases, so each tier runs its newest model; nothing runs above high. Check the actual model and effort and name them in the receipt. A substitution blocks only a review or gate verdict that ran below its pinned tier, because that verdict no longer has the judgement it was priced for; any other substitution is a note.
- Save disposable evidence under `artifacts/local/`; preserve historical evidence and owner changes. Report the checked version and method. Automated play does not establish human feel or physical hardware support.
- Update the relevant ADR when a durable decision changes. Keep definitions in BACKLOG and execution state in TRACKING. A project note creates no reminder, scheduled work or persistent memory.

## Steps that need no approval

Act, then report. These are safe to repeat, or Andrew's standing approval covers them (27 Oct, widened 9 Nov):

- Retry any call that is safe to repeat when it fails, times out or finds a tool busy: reads and searches, `git fetch` and pushes to your own branch, tests, `npm run sketch:fast`, gate shards, bot runs, band sweeps, Godot imports and builds. Rerun a red alone before calling it ([GATE.md](project-guide/handoff/GATE.md)). A retry is not a new attempt.
- Commit, push and open draft PRs on your own branch; edit `src/`, `assets/`, `tools/`, `registry.d`, tests and docs there.
- Stack gate-passed PRs onto the stage, promote the stage to main, cut the next stage, and push `stage/*`, `cand/*` and `scratch/*` branches (the Gate and the coordinator).
- Decide game mechanics and tuning taste within the rulings, and record each as a one-line assumption Andrew can overturn.
- Write and update memory, library files, handoffs and private artifacts; resolve finished threads.

Get Andrew's go-ahead first for: deleting anything (merged-branch deletes go to his prune script as a list with recovery SHAs), a force-push or history rewrite, an edit to `sketches/core-loop/package.json`, anything outside the repo, and anything in `~/.local/share/godot/app_userdata/core-loop` (his saves and settings). Once he approves one, it has its go-ahead. The PC lane runs Godot only with the scratch folder, and the PC safety check stays as it is.
