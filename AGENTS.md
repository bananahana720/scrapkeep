# Scrapkeep project instructions

Read [the project desk](docs/project/README.md) and [CONTRIBUTING.md](CONTRIBUTING.md) before substantive work. Personal A stack preferences and host policy still apply. The game is a Godot sketch at `sketches/core-loop` with three worlds. Alpha waves 17 to 21 are coordinated from the local Claude Code session on Andrew's PC, with Claude Code cloud lanes. The live board is [project-guide/coord/GRAPH.md](project-guide/coord/GRAPH.md) plus GitHub issue #241, and the rulings are in [project-guide/handoff/DECISIONS.md](project-guide/handoff/DECISIONS.md). Alpha work stacks on `stage/alpha-w<N>`, and Andrew plays once, at the end of wave 21.

- `BIBLE.md` and accepted `adr/` records own game and production direction. `BACKLOG.md` owns task definitions, `TRACKING.md` owns live execution and questions, and `ORCHESTRATOR.md` owns assignment, isolation, review and integration. Read the task's exact sources; a proposed sprint or ready card is not authorization to start it.
- Use `plan-session` for planning, `scrapkeep-task` for authorized cards, `scrapkeep-verify` for artifact-specific verification, `scrapkeep-lab` for the headless Godot lab, `scrapkeep-blockout` for mojulo blockout pieces and their ball proofs, and `reactive-model-loop` for a fast model that decides inside a running system. The skill bodies live under `.agents/skills/`, linked into `.claude/skills` (`reactive-model-loop` mirrors its canonical pstack copy); `.agents/skills/README.md` says when to add a skill, and `npm run check:skills` checks them.
- Preserve `/` and `/orchard.html` as separate browser proofs (preserved proofs, not the current direction) until consolidation is explicitly approved. Their tests do not qualify the future native game.
- Keep orchard combat state in `src/orchard/simulation.js`, rendering in `scene.js`, procedural models in `models.js`, and input/UI orchestration in `main.js`. Consult the lightning integration contract before changing interfaces. Damage and telegraphs consume the same committed geometry.
- Use locked dependencies and existing free local tools. Housekeeping does not authorize dependency upgrades, engine migration, new game features, paid services or deployment; light-play-lane sketches are the authorized exception for game features.
- For completed browser-proof code changes, run `npm run verify` and the applicable browser checks in CONTRIBUTING. For documentation/configuration-only work, use scoped structure, link and behavioral checks; do not run builds under a no-build scope. Native checks come from the approved engineering handoff, not guessed commands. Godot sketches under `sketches/` follow ORCHESTRATOR's light play lane: `npm run sketch:smoke`, Andrew plays, playtest log, merge. The gate for alpha PRs and promotions (focused tests plus `npm run sketch:fast` per PR, the full gate once per promotion) is ORCHESTRATOR's tiered gate; it is the only owner of that rule.
- Writing agents use disjoint worktrees with verified base identity. The coordinator alone admits changes and writes canonical execution records. Follow ORCHESTRATOR's scoped prose-staging exception. Claude project agents are the only workers (the Codex lane retired on 17 October 2026). The definitions in `.claude/agents` own the pins and pin Sonnet 5.5 at medium for writing, lookup and mechanical edits (Andrew, 2026-09-28 trial: Sonnet where speed can be afforded), Opus 5.5 at medium for routine review and the acceptance gate (family aliases, so each tier runs its newest model), and Fable 5.1 at high for consequential review; nothing runs above high. Read the model map, check actual model/effort, and report substitutions as blockers.
- Save disposable evidence under `artifacts/local/`; preserve historical evidence and owner changes. Report the checked version and method. Automated play does not establish human feel or physical hardware support.
- Update the relevant ADR when a durable decision changes. Keep definitions in BACKLOG and execution state in TRACKING. A project note creates no reminder, scheduled work or persistent memory.
