# Scrapkeep project instructions

Scrapkeep is a Godot roguelite at `sketches/core-loop` with three worlds. The goal is a finished-feeling Linux alpha. Under ruling ep, Worlds 1–3 are unparked in the unified pre-alpha baseline on `main`; Andrew plays a world 1 sitting, then one full-alpha sitting, and no wave asks him to play. One local session on the Mac Studio coordinates the work and is the Gate (rulings ds and eb): it talks to Andrew in its own chat, plans the work, and builds each unit itself or through a worker in a separate worktree. Rule 11 names the workers. The rules below say "thread" from the claude.ai project period (ruling dh, 12 to 14 Nov); they bind the local session and its writer agents the same way. Andrew's pstack preferences (the public plugin from `cursor/plugins`, ruling er) and host policy still apply; where a pstack playbook and these rules differ, these rules win.

2. [STATE.md](project-guide/handoff/STATE.md): the open stage and the live board. Under ruling ep, work runs flat on `main` (`Open stage: main`, `Live board: none`), retiring legacy per-wave `stage/alpha-w<N>` stacking.

## Rules, most important first

1. **Finish every to-do** (ruling dn, Andrew, 14 November 2026). Keep going until every task is done, including tasks Andrew or the coordinator add later. Before you say "done" or go idle, read the original ask again and list each task as done (with its pull request or file), handed off (to whom) or not done. Finish what is not done. A PC session waits on a background job for at most about 45 minutes, then takes a short turn ([DEVICES.md](project-guide/handoff/DEVICES.md)).
2. **One thread, one writer** (ruling by). A project thread writes its own changes, runs its own checks and owns its pull request from claim to merge. It starts a sub-agent only for work that writes nothing and returns a short finding: wide search, research, a long noisy run, and the independent review of its finished diff. Work too big for one thread goes to the coordinator to split.
3. **Only the Gate lands changes on the open branch** (ruling ds, 15 Nov 2026; flattened onto `main` by ruling ep). One local session is the coordinator and the Gate; since ruling eb (16 Nov) it runs on the Mac Studio, not the PC. It alone integrates reviewed pull requests onto the open branch (`main` under ruling ep, formerly `stage/alpha-w<N>`), runs the gate, promotes, and runs the PC work. A writer agent it starts opens a draft pull request against the open branch and reports back; "the board thread" in older pages means this session.
4. **Every pull request gets focused tests, `npm run sketch:fast -- --base main` and one independent review.** The reviewer is a fresh Gemini 4 Neon session at high (rule 11) that gets the diff and what done looks like, not the writer's reasoning; no session reviews its own diff. The wave gate runs once per promotion and the release gate once per sprint. [ORCHESTRATOR.md](ORCHESTRATOR.md)'s tiered gate is the only owner of that rule. Rerun a red alone before you call it red ([GATE.md](project-guide/handoff/GATE.md)).
5. **Write for a reader with no context** (ruling cz). Every board post, receipt, brief, report and hand-off stands on its own, leads with what changed or what the reader must do, and uses plain words with no term made up during the work. A cloud session cannot see the PC's disk, so name a pushed branch, a pull request or a repo file, never a local path alone. [COMMS.md](project-guide/handoff/COMMS.md) has the rules.
6. **One home for every fact** (ruling bz). Update the page that exists before you make a new one, link instead of repeating, and add anything new to the library in the same turn. A rule or procedure that binds every session lives in this file or a page it links, never only in one session's private memory or a local hand-off note (Andrew, 21 November 2026).
7. **Deep modules, simple interfaces** (Andrew, 9 November 2026). Put new behaviour inside the module that owns the state and give callers one small call, never a reach into private members. Do not widen an interface to save a few lines. [DEEP-SWEEP.md](project-guide/handoff/DEEP-SWEEP.md) has the method.
8. **No slop in anything the player meets** (ruling cx). Before a word goes on a screen, ask whether position, shape, colour, an icon, motion or sound should carry the fact instead. No eyebrow labels, no heading that restates the screen, no label that restates its value, one name for one thing, no filler. Keep the game's voice. [LEGIBILITY.md](sketches/core-loop/design-v3/LEGIBILITY.md) section 13 has the pattern list and the carrier order; a change a player can read or navigate is written and reviewed against it.
9. **World 1 design directions** (rulings ct, cu and cv). Every map is held to the ten-point map standard. Difficulty is tuned harder, never easier: hardness presses a ball that slows or stops, and never stops a ball that keeps rolling and turning. A world plays as one ride with no hard cut between stages. Read the audit for the area in [shared/world1/](project-guide/handoff/shared/world1/) before you change a map, the difficulty or a hand-over.
10. **Read the story and tone first for creative work**: [STORY-MAP.md](sketches/core-loop/design-v3/STORY-MAP.md) and [TONE-BIBLE.md](sketches/core-loop/design-v3/TONE-BIBLE.md) before design, art or sound.
11. **Workers by kind of work** (ruling ej, Andrew, 21 November 2026; widened 21 November; for work the Gate starts it replaces the tier pins of ruling bp). Claude Fable 5.2 leads design, planning, coordination and orchestration: the coordinator and Gate session runs on it, splits the work into units and writes each brief. Claude Opus 5.5 takes the 3D-related and UI-related units: meshes, map and park geometry, placement, blockout, look and lighting, UI screens, HUD and controls, and the stills that prove them. Gemini 4 Neon takes everything else: game code, research, tests, formal models, band reads, gate runs, re-pins, records, and the independent review of every unit, the 3D and UI ones included. All three run at high effort and nothing runs above it. Pick the worker by what the unit mostly is; a unit in flight keeps its writer for its fix round (rule 2). GPT 6.2 Astra and Sol may assist with the world 1 promise cards, QA passes, concept art, model drafts and a second review opinion (rulings ec and ee; Andrew, 19 November 2026); their verdicts are evidence and do not admit a unit. No older model version stands in for a named one (never `claude-opus-4-6`). The definitions in `.agents/agents` and `.claude/agents` keep the older tier pins and are the fallback when a named worker cannot run. Name the actual model and effort in the receipt. A substitution blocks only a review or gate verdict that ran on a model other than the one this rule names; any other substitution is a note. "Running workers and machines" below has the method.
12. **Evidence.** Save disposable evidence under `artifacts/local/`; preserve historical evidence and owner changes. Report the checked version and the method. Automated play does not establish human feel or physical hardware support.
13. **Use locked dependencies and free local tools.** The go-ahead list below covers what changes what Andrew pays for or ships.

## Steps that need no approval

Act, then report. Andrew's standing approval covers these (27 October, widened 9 November):

- Retry any call that is safe to repeat when it fails, times out or finds a tool busy: reads, searches, `git fetch`, pushes to your own branch, tests, `npm run sketch:fast`, gate shards, bot runs, band sweeps, Godot imports and builds. A retry is not a new attempt.
- Commit, push and open draft pull requests on your own branch; edit `src/`, `assets/`, `tools/`, `registry.d`, tests and docs there.
- The Gate (the local session, ruling ds; flattened onto `main` by ruling ep) integrates reviewed pull requests onto `main`, and pushes `stage/*`, `cand/*` and `scratch/*` branches when needed.
- Decide game mechanics and tuning taste within the rulings, and record each call as a one-line assumption Andrew can overturn.
- Write and update memory, library files, hand-offs and private artifacts; resolve finished threads.

**Get Andrew's go-ahead first for:** deleting anything (merged-branch deletes go to his prune script as a list with recovery SHAs; other candidates go in `housekeeping/pending-deletes.md` in the project's shared folder, `/mnt/project-files/`), a force-push or history rewrite, an edit to `sketches/core-loop/package.json`, a dependency upgrade, an engine migration, a paid service, a deployment, anything outside the repo, and anything in `~/.local/share/godot/app_userdata/core-loop` (his saves and settings). A housekeeping task is not that go-ahead. Once he approves one, it has its go-ahead. The PC runs Godot only with the scratch folder, and the PC safety check stays as it is.

## Running workers and machines

- **Starting a worker.** The Gate starts each worker through the host's delegation tool, each writer in its own worktree. In T3 Code that is `delegate_task`, after one `orchestrator_capabilities` call per thread: Fable 5.2 is `claude-fable-5-2` and Opus 5.5 is `claude-opus-5-5` on the Claude provider with `effort: high`; Neon is `gemini-4-neon` on the Antigravity provider with `thought_level: high`; Astra and Sol are `gpt-6.2-astra` and `gpt-6.2-sol` on the Codex provider.
- **Every brief** stands on its own (rule 5) and names the base commit, the branch, the files the unit may change, the checks and the report wanted. A writer confirms the base with `git rev-parse HEAD` before its first write and stops on a mismatch. Every brief also says: run every shell, Godot, test and lint command in the foreground to completion, and never end a turn while a command still runs in the background. A delegated worker that does is marked finished too early.
- **Reviews.** A reviewer reads the pushed head with read-only git and writes nothing. It leads with `VERDICT: PASS` or `VERDICT: FAIL`, lists blocking issues apart from notes, says whether a small fix by the Gate needs another review, and ends with a receipt: its model and effort, the commits checked, the method and what it did not do. The Gate fixes a small note itself while integrating and sends a blocking issue back to the unit's writer.
- **Integrating.** Under ruling ep, the Gate integrates passed pull requests onto `main` (and historically stacked `stage/alpha-w<N>`) in a checkout no worker uses, runs focused tests and `npm run sketch:lint` there, and pushes; the pre-push hook must pass.
- **Machines.** The Mac Studio is the Gate machine (ruling eb) and is for the agents' use alone, so checks run wide. The Linux PC ("ahana") is free hardware for checks, gate shards, builds and GPU readings (Andrew, 19 November 2026); an install there still needs his go-ahead. Godot on either machine runs only with a scratch data folder, and a Mac reading is never compared with a Linux one. [DEVICES.md](project-guide/handoff/DEVICES.md) has the shell lines, the save isolation and how each machine is reached.

## Reference

- **Skills.** All 11 project skills live under `.agents/skills/` (symlinked into `.claude/skills/`) and are indexed in [.agents/skills/README.md](.agents/skills/README.md); `npm run check:skills` validates them. Antigravity and Gemini sessions start at [GEMINI.md](GEMINI.md) and use `.agents/` (`rules/`, `agents/`, `hooks.json`).
- **Game work rides the light play lane**, ORCHESTRATOR's lane for the Godot sketch under `sketches/`. The per-pull-request checks are rule 4. Native checks come from the approved engineering handoff, not guessed commands.
- **Documentation and configuration work** uses scoped structure, link and behaviour checks. Do not run builds under a no-build scope.
- **The older heavy lane** (ORCHESTRATOR's card-and-board process, for work outside the sketch). [START-HERE.md](project-guide/handoff/START-HERE.md) is the live start page. `BIBLE.md` and accepted `adr/` records own game and production direction, `BACKLOG.md` owns task definitions, `TRACKING.md` owns heavy-lane execution and questions, and `ORCHESTRATOR.md` owns assignment, isolation, review and integration. A proposed sprint or a ready card is not authorization to start it. Update the relevant ADR when a durable decision changes. In a local coordinator session that runs writer agents, each writer gets its own worktree with a verified base, and the coordinator alone admits changes and writes the canonical records; follow ORCHESTRATOR's scoped prose-staging exception.
- **The browser proofs.** `/` and `/orchard.html` are preserved proofs, not the current direction; keep them separate until consolidation is approved. Their tests do not qualify the native game. For a change to them, run `npm run verify` and the browser checks in CONTRIBUTING. Orchard combat state stays in `src/orchard/simulation.js`, rendering in `scene.js`, procedural models in `models.js`, and input and UI in `main.js`; read the lightning integration contract before you change an interface. Damage and telegraphs consume the same committed geometry.
- **Shared-process test cleanup & pre-push hook.** Warm-batched Godot tests ([test_batch_driver.gd](sketches/core-loop/tools/test_batch_driver.gd)) share one engine process and reset `tree.root` children, `tree.paused`, `Engine.time_scale`, physics tick rates and `ChallengeDials.reset()` after each file; any new static/global state must reset in `_reset()` (or mark the test solo) and pass under `npm run sketch:fast -- --shuffle`. Node tests must clean up temp dirs in `finally` blocks and pass under `node scripts/ci/node-tests.mjs --shuffle`. Local clones enforce fast (<9s) pre-push checks via [scripts/hooks/pre-push](scripts/hooks/pre-push) (`npm run hooks:install`, wired into `prepare`).
- A project note creates no reminder, scheduled work or persistent memory.
