Start with the [project desk](docs/project/README.md). ## Install and run

Use Node matching `package.json#engines` and the committed lockfile. The declared range follows the installed Vite requirement. This session ran Node 26.8.1; other supported versions have not been checked here.

```sh
npm ci
npm run dev
```

Vite serves the orchard at `http://127.0.0.1:5173/orchard.html` and the original yard at `/`. Only the baseline signup flow needs the separate API server. For a built local playtest with contact capture disabled:

```sh
npm run build
CAPTURE_ENABLED=false npm start
```

Open `http://127.0.0.1:8787/orchard.html`. If a port is occupied, inspect the owner before changing or stopping it. Vite prints its actual URL. Environment settings are documented in [.env.example](.env.example) and [lead capture](docs/LEAD-CAPTURE.md). `npm start` does not load a .env file implicitly.

## Verification

```sh
npm run verify
```

This runs project checks, the Node tests matched by `tests/*.test.js`, model invariants, the asserted baseline expedition check, a production build, and temporary-port HTTP checks for both entries and their linked assets. The frozen lead-capture suite under `tests/legacy/` is not part of it; run `npm run test:leads` separately. Each stage stops on failure. Logs, source hashes, and a machine-readable result go to `artifacts/local/verify/`. The built-entry stage starts a minimal static server for `dist/` on a temporary port, asserts that `/api/config` returns 404, and closes it. It does not start the lead-capture server, stop the user's server, or run browser automation.

Scope-to-command map. Run `npm run check:scope -- <base> <candidate>` on a candidate first. Documentation-only changes need `npm run check:docs`, `npm run check:project` and `npm run check:drift` and no build. A `tooling-no-build` change, confined to `scripts/*.mjs`, `tests/*.test.js`, `package.json` scripts entries and documentation, needs `npm test` and those same three checks and no build. Browser-proof or build-requiring tooling changes need `npm run verify`, plus the browser checks below where UI paths changed. Production native changes wait for `check:godot`. Operational Sprint 0 is the explicit [authorized proof exception](docs/project/sprint-0/AUTHORIZATION.md): run `node scripts/native-smoke.mjs --export` for the integrated editor, Linux and Windows exports, and Linux fresh-process/offline checks. The scope selector still prints the reserved command; use this named exception for these cards only. Configuration changes need `check:docs` and a scenario review against ORCHESTRATOR.md and AGENTS.md. A mixed set needs the union. Hosted CI remains parked. Operational Sprint 0 uses a manually dispatched local self-hosted workflow after explicit runner-registration approval; its Linux execution is required closure evidence. See the [toolchain record](docs/tech/native-toolchain.md) for commands and report limits.

Set `CHROMIUM_PATH` for a non-default browser path and `GAME_URL` for the baseline replay's Vite origin. The supported interactive paths are:

- Baseline development `/?qa&quality=low`: **Run regression replay**. Baseline QA is excluded from production.
- Orchard development or production `/orchard.html?qa`: **Run DOM input replay**, **Run state fixtures**, and **Run input expedition**. Record them separately. Fixture screenshots stage state; the input expedition uses ordinary handlers with scripted precision. **Run 60-second bounded stress** stages durable enemies and the full build, then requires normal simulation, rendering and attack activity for sixty seconds. Its JSON records graphics identity, frame samples, simulation advancement and renderer counters. Keep the tab visible during replays.
- A normal URL: inspect start, gameplay, pause/help, results and restart after presentation changes. Test actual hardware before claiming controller or mobile support.

No browser session, human enjoyment, or performance benchmark is implied by `npm run verify`.

## Asset inspection

Use the [asset inspector](docs/ASSET-TOOLING.md) before admitting an exported GLB or assembling parts from a model collection. It reads local files, counts actual exported geometry and checks an explicitly selected budget. Inventory is not approval. A budget pass does not prove engine import, visual quality or rendered performance. The tool does not change meshes or replace the sketch's Godot asset tests.

## Jev Lab

The Jev Lab plays the light-lane sketches headless with seeded `random` and `scripted` arms, records each batch as a `scrapkeep-run/1` record, gates a batch against a pin, and shows every lab, program and human metric on a local dashboard. Automated play is not a feel verdict; only Andrew's play settles feel. The [lab skill](.agents/skills/scrapkeep-lab/SKILL.md) owns how to run and extend it, the [reactive-model-loop skill](.agents/skills/reactive-model-loop/SKILL.md) owns the method for any Jev decider, and the [Jev player README](tools/jev-player/README.md#jev-lab-tools-and-their-measured-limits) gives each tool's measured limits with the event that measured it. The program's results are in the [Jev Lab retro](artifacts/jev-lab-2026-09-25/RETRO.md).

```sh
node scripts/lab/godot-launch.mjs <scenario> --arm scripted -n 20  # one headless batch on real Godot
npm run play -- gate <run_id> --against <pin>                      # 0 pass, 1 differs or red, 2 usage, 3 inconclusive, 4 instrument invalid
npm run play -- stats --layer program                              # one line per metric
npm run play -- dash                                               # writes artifacts/local/dash/index.html
npm run play -- lab watch <scenario> --arm scripted|random|jev     # one visible trial; a demo, never evidence
```

In the watch view, M marks a moment with a note, T shows the state text, S steps the speed through 1×, ½× and ¼×, and H shows the keys. `--arm jev` makes live Jev calls, 60 by default including the preflight. Jev's four advisory test-loop tools (failure triage, verdict tagging, coverage gap, test ordering) are listed with their scores and caveats in the [Jev player README](tools/jev-player/README.md#jev-test-loop-tools). Test ordering runs inside `npm run play -- watch`. The others are run by hand: triage and coverage gap call Jev whenever a key is found, and verdict tagging only with `--live`. Jev-as-player is parked, so the jev arm refuses evidence batches (preflight exit 6). None of these is a `verify` stage, and nothing on the gate path calls Jev.

## Editing conventions

Use native JavaScript ES modules, two-space indentation, double quotes, semicolons, and the installed Prettier on files you change. Avoid repository-wide formatting while fixing one issue. Keep functions and data near their actual callers; introduce shared code when both entries need the same behavior, not merely similar names.

Gameplay constants belong in the simulation. Detailed values stay in code and the integration contract rather than being copied into every document. Explain a non-obvious invariant in a comment; do not narrate routine code. Add tests for a concrete failure or gameplay invariant, and name the behavior they establish.

Use an ADR for a durable module boundary, delivery/runtime choice, or data/asset ownership decision. Amend its status or supersede it when the decision changes. Product feature ideas go in the backlog first. The source-of-truth map prevents a new session summary from replacing accepted requirements.

## Handoff and version control

After a change, update its canonical docs, record executed checks and material limits, and record execution state and the next action in TRACKING.md. A light-play-lane sketch (ORCHESTRATOR, Light play lane) records its checks, Andrew's verdict and the next action in [the playtest log](docs/playtests/PLAYTEST-LOG.md) instead. BACKLOG.md owns definitions, not live status. The append-only [decision trail](docs/decisions.tsv) records meaningful choices, not every command.

The repository preserves local history beginning at baseline `4db9b31`. Andrew authorized the private GitHub repository `bananahana720/scrapkeep`, with `main` as the default branch and publication of `main` and the `stage/alpha-w<N>` branches. [TRACKING.md](TRACKING.md) records the actual publication state and verified revision. Inspect the current branch and worktree before editing; never infer them from a historical receipt. Commit reviewed changes before integrating, preserve owner work, and keep writing agents in disjoint worktrees. Experimental branches remain local unless separately authorized.

Keep `node_modules/`, `dist/`, secrets and disposable evidence untracked (see `.gitignore`). [Artifact retention](artifacts/README.md) and [asset provenance](docs/project/ASSETS.md) describe the remaining buckets.
