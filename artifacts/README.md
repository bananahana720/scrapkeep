# Verification artifacts

There are two kinds of output in this directory.

- Named build records, including `orchard-first-build/`, earlier screenshots, JSON receipts and `visual-iterations/`, are historical evidence. Their source version, test method and limitations belong in the linked verification document. Historical JavaScript snapshots are not active source. Where a record once held a full source copy, an `implementation-manifest.json` with per-file sha256 and byte sizes plus a diff against the live source replaces it.
- `local/` is disposable, ignored output from current commands. `npm run verify` writes `local/verify/`; the browser wrappers and balance probe write here by default. `ARTIFACT_DIR` can select another destination for those wrappers/probes. Do not point it at a retained build record.

Rerunning a test must not silently replace a dated claim. When retaining a new result, copy the needed files to a named build/session directory, record source hashes or a real commit, commands, date, outcome and evidence type, and link that record from the owning verification document. A PASS from a fixture is not a human playthrough.

The existing records were preserved during closeout. [Lightning verification](../docs/LIGHTNING-VERIFICATION.md) owns the new `lightning-playtest/` record. [First-build verification](../docs/FIRST-BUILD-VERIFICATION.md) remains the historical first-proof evidence owner. [Housekeeping](../docs/project/HOUSEKEEPING.md) owns this closeout. The new local verification report overwrites its own disposable previous run and records whether every planned stage ran.

## Disposal contract for pin-critical local evidence

`local/` is disposable, but a tracked authority record can still pin bytes inside it. Before deleting, pruning or `git clean`-ing anything under `artifacts/local/`, run the read-only pin check from the repository root:

```sh
node scripts/sprint-close.mjs docs/project/sprint-0/closure.json
```

It reads the receipt, hashes every pinned evidence file and prints its `issues`; a path reported as missing or hash-differing means the tracked record can no longer be replayed. The `path` + `sha256` walk written by card AR-02 at `artifacts/local/tasks/AR-02/pin-walk.py` additionally requires each pinned path to be tracked by Git, but it lives in that same disposable scratch and may be gone. Copy anything a tracked record still cites into a retained directory first — copying, never moving, is the rule, and regenerating a gate at the pinned source is not the same files.
