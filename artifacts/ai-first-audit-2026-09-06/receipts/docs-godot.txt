### Export project from the command line using Godot

Source: https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html

Requires the Godot editor binary and installed export templates configured with matching preset names. Using `--headless` is required on environments without GPU access to avoid spawning editor windows.

```bash
# `godot` must be a Godot editor binary, not an export template.
# Also, export templates must be installed for the editor
# (or a valid custom export template must be defined in the export preset).
godot --headless --export-release "Linux/X11" /var/builds/project
godot --headless --export-release Android /var/builds/project.apk

```

### Define a Standalone Script in GDScript

Source: https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html

Scripts executed from the command line must inherit from SceneTree or MainLoop. Call quit() when processing finishes to exit the engine process.

```gdscript
#!/usr/bin/env -S godot -s
extends SceneTree

func _init():
    print("Hello!")
    quit()

```

### Command line reference

Source: https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html

Godot provides command-line options for running scripts and exporting projects. Using `--script` allows executing a script via a relative resource path or an absolute filesystem path. Projects can be exported from the command line using `--export-release`, `--export-debug`, or `--export-pack` with a specified preset, where the target path includes the output filename and its extension determines whether pack exports use PCK or ZIP format.

--------------------------------

### Exporting

Source: https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html

Godot supports exporting projects from the command line for release or debug builds, as well as exporting standalone PCK or ZIP packages. The `--headless` command-line argument is required on platforms lacking GPU access (such as CI runners) and prevents an editor window from spawning. Preset names passed to the export command must match presets defined in the project's `export_presets.cfg` file. When using relative output paths with export arguments, paths are resolved relative to the directory containing `project.godot`, not the current working directory.

### Define a custom Resource class in GDScript and C#

Source: https://docs.godotengine.org/en/4.7/tutorials/scripting/resources.html

Ensure custom Resource constructors provide default arguments or a parameterless constructor for proper Inspector instantiation. Register the class using `class_name` in GDScript or `[GlobalClass]` in C#.

```GDScript
class_name BotStats
extends Resource

@export var health: int
@export var sub_resource: Resource
@export var strings: PackedStringArray

# Make sure that every parameter has a default value.
# Otherwise, there will be problems with creating and editing
# your resource via the inspector.
func _init(p_health = 0, p_sub_resource = null, p_strings = []):
	health = p_health
	sub_resource = p_sub_resource
	strings = p_strings

```

```C#
// BotStats.cs
using Godot;

namespace ExampleProject
{
    [GlobalClass]
    public partial class BotStats : Resource
    {
        [Export]
        public int Health { get; set; }

        [Export]
        public Resource SubResource { get; set; }

        [Export]
        public string[] Strings { get; set; }

        // Make sure you provide a parameterless constructor.
        // In C#, a parameterless constructor is different from a
        // constructor with all default values.
        // Without a parameterless constructor, Godot will have problems
        // creating and editing your resource via the inspector.
        public BotStats() : this(0, null, null) {}

        public BotStats(int health, Resource subResource, string[] strings)
        {
            Health = health;
            SubResource = subResource;
            Strings = strings ?? System.Array.Empty<string>();
        }
    }
}

```

### @export()

Source: https://docs.godotengine.org/en/4.7/classes/class_%40gdscript.html

Marks a property as exported so that it is editable in the Godot Inspector dock and serialized to disk. Supports built-in types, enums, resources, nodes, and typed arrays.

```APIDOC
### Annotation: @export()

#### Description
Mark the following property as exported (editable in the Inspector dock and saved to disk). To control the type of the exported property, use standard GDScript type hint notation.

#### Syntax
```gdscript
@export var property_name: Type = default_value
```

#### Notes
- Custom resources and nodes should be registered as global classes using `class_name`.
- Node export is only supported in `Node`-derived classes.
```

### @export_storage

Source: https://docs.godotengine.org/en/4.7/classes/class_%40gdscript.html

Exports a property with storage flags so it is serialized and stored in scene or resource files without being displayed in the Inspector. Also ensures the property value is copied during object duplication.

```APIDOC
## Annotation: @export_storage

### Signature
`@export_storage()`

### Description
Export a property with the `@GlobalScope.PROPERTY_USAGE_STORAGE` flag. The property is not displayed in the editor, but it is serialized and stored in the scene or resource file. Useful for `@tool` scripts. The property value is copied when `Resource.duplicate()` or `Node.duplicate()` is called.

### Parameters
*None*

### Usage Example
```gdscript
var a # Not stored in the file, not displayed in the editor.
@export_storage var b # Stored in the file, not displayed in the editor.
@export var c: int # Stored in the file, displayed in the editor.
```
```

### ResourceSaver > Description

Source: https://docs.godotengine.org/en/4.7/classes/class_resourcesaver.html

ResourceSaver is a singleton used for saving resources to the filesystem. It utilizes registered ResourceFormatSaver classes (built-in or from plugins) to write resource data to text-based files such as .tres or .tscn, as well as binary files like .res or .scn.

### FileAccess.open

Source: https://docs.godotengine.org/en/4.7/classes/class_fileaccess.html

Opens a file at the specified path using the provided mode flags. Returns a FileAccess instance configured for read or write operations.

```APIDOC
## FileAccess.open(path, flags)

### Description
Creates and opens a new FileAccess object to read from or write to the file at the specified path.

### Method
`static open(path, flags)`

### Parameters
- **path** (String) - Path to the file (e.g., `"user://save_game.dat"`).
- **flags** (ModeFlags) - Mode flag determining read/write permissions (e.g., `FileAccess.READ`, `FileAccess.WRITE`).

### Example (GDScript)
```gdscript
var file = FileAccess.open("user://save_game.dat", FileAccess.WRITE)
```

### Example (C#)
```csharp
using var file = FileAccess.Open("user://save_game.dat", FileAccess.ModeFlags.Write);
```
```

### void close()

Source: https://docs.godotengine.org/en/4.7/classes/class_fileaccess.html

Closes the currently opened file and prevents subsequent read and write operations. To persist data to disk without closing the file, use flush instead.

```APIDOC
## Method: close

### Signature
```gdscript
void close()
```

### Description
Closes the currently opened file and prevents subsequent read/write operations. Use flush() to persist the data to disk without closing the file.

**Note:** **FileAccess** will automatically close when it's freed, which happens when it goes out of scope or when it gets assigned with `null`. In C# the reference must be disposed after we are done using it, this can be done with the `using` statement or calling the `Dispose` method directly.
```

### String get_user_data_dir() const

Source: https://docs.godotengine.org/en/4.7/classes/class_os.html

Returns the absolute directory path where user data is written (the user:// directory in Godot). The path varies depending on the project name, settings, and host operating system.

```APIDOC
## String get_user_data_dir() const

### Description
Returns the absolute directory path where user data is written (the `user://` directory in Godot). The path depends on the project name and `ProjectSettings.application/config/use_custom_user_dir`.

### Platform Behavior
- **Windows**: `%AppData%\Godot\app_userdata\[project_name]` (or `%AppData%\[custom_name]` if `use_custom_user_dir` is set). `%AppData%` expands to `%UserProfile%\AppData\Roaming`.
- **macOS**: `~/Library/Application Support/Godot/app_userdata/[project_name]` (or `~/Library/Application Support/[custom_name]` if `use_custom_user_dir` is set).
- **Linux/BSD**: `~/.local/share/godot/app_userdata/[project_name]` (or `~/.local/share/[custom_name]` if `use_custom_user_dir` is set).
- **Android/iOS**: Sandboxed directory in internal or external storage.
- **Web**: Virtual directory managed by the browser.

### Return Value
- **String** - The absolute path to the user data directory. If the project name is empty, `[project_name]` falls back to `[unnamed project]`.
```
