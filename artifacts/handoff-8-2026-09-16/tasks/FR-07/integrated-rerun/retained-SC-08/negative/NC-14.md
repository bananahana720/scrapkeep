## Contract

### What this contract fixes

Five definition types, T1 to T5, cover the four HF-06a schema rows in this family. Two excluded rows are confirmed as exclusions. Each type has fields, identity and version rules, references, diagnostics and one illustrative record. Every reference is a domain ID. Every durable trace is an ID in one of two existing profile fields. No type has an effect, a counter, a timestamp, a durability class or any numeric field.

Counts for a reviewer: six allocated rows, five types, nine foreign resolution rows, nine common diagnostics, one restore diagnostic, fifteen type-specific diagnostics, eight identity and version rules, five engine-form rules, six qualification obligations, seventeen parameter rows (two with a source value, fifteen `unset` with a question ID), seven seams and seven walks.

| ID | Rule | Source |

### Common diagnostics

Every type's validation runs in ContentAdmission alone (HF-03a line 34). An initial candidate that fails the structural gate leaves `imported` by E08; a replacement leaves by E11. An initial candidate that fails the semantic gate leaves `structurally valid` by E09; a replacement leaves by E12 (HF-05 lines 87 to 92). Each `ContentReferenceFailure` carries `operation` `validate_candidate`, the exact `requested_id`, the field's allowed family set as `expected_family`, the candidate's `requested_content_revision`, `referrer` as the definition ID plus field path and index (HF-05 line 111), and `held_operation` the candidate admission. Its `message_key` belongs to the interface contract (HF-05 line 115).
