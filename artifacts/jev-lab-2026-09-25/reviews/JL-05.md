### Non-blocking findings (ordered by consequence for JL-09/JL-11/JL-14/JL-17/JL-21)

1. **`k < D` rule collides with the JL-21 sweep.** `PROTOCOL.md:32` and `protocol.mjs:272-278` make `hold_ticks >= snapshot_every` invalid, and `PROTOCOL.md:104` relies on `k < D` for the `held` invariant. `artifacts/jev-lab-2026-09-25/plan.md:136` sweeps D ∈ {45, 90} and k ∈ {0, 26, 54}; the pair (45, 54) is invalid under v1. Not a JL-05 defect (the plan's own schedule implies k < D) but the coordinator should note it on JL-21: exclude k ≥ D or plan a v2.

2. **`offeredOptions()` duplicates decide.mjs's inline fallback.** `protocol.mjs:244-249` re-implements `decide.mjs:170-173`. The fallback is not exported from decide.mjs (it is a local inside `decide()`), and decide.mjs is outside this card's boundary, so importing was not possible without a scope breach. It is a validation-drift risk: `GATE_VERSION` (`decide.mjs:25-26`) protects the cache key but not the validator. Recommend a follow-up on whichever card next touches decide.mjs (JL-11 or JL-14): export `offeredOptions` from decide.mjs, have `decide()` and protocol.mjs both call it. The test at `protocol.test.js:267-277` pins the current behaviour but cannot detect divergence.

3. **Rules in `protocol.mjs` that `PROTOCOL.md` does not state** (JL-09 reimplements from doc + fixtures, so these are the gaps a GDScript port would miss):
   - Grid tolerance: `protocol.mjs:47-49` uses `|v/step − round(v/step)| < 1e-9`; the doc says only "steps of 0.1" (`PROTOCOL.md:141,146,149`).
   - `events.ndjson` must end with `\n` and an empty file is valid (`protocol.mjs:438-441`); the doc (`:79-93`) says neither, nor that line endings are LF (the test at `protocol.test.js:114` enforces no CR on fixtures only).
   - `tick_hz`, `snapshot_every`, `intent_timeout_s` must be > 0 (`protocol.mjs:267-271`); doc `:32` does not say so.
   - Any non-protocol file name in `<io>` is an error (`protocol.mjs:519-529`); doc `:7` does not say the directory must contain nothing else (Node-side only, so lower priority).
   - Conversely the doc states "at an equal tick, an `intent` line comes before the `trace` line" (`PROTOCOL.md:93`) and `validateEvents` does not check it (`protocol.mjs:464-472` only enforces non-decreasing). Either enforce it or mark it as a Godot write-order rule that is not validated. It does affect `trace_hash`, so it is binding on JL-09 regardless.

4. **`trace_hash` cross-implementation answer: reproducible, because nothing re-serialises.** Godot hashes the bytes it wrote; Node hashes the same file (`protocol.mjs:489-491`, `:641-649`; doc `:77`). Number formatting differences between Godot and Node's `JSON.stringify` (the fixtures were generated by Node, `gen-fixtures.mjs:116`) therefore do not matter for JL-09's fixture copy or JL-17's delay test. The only formatting-sensitive artifact is `canonicalJson`/`verdictKey` (`protocol.mjs:711-740`), which uses JS `.sort()` (UTF-16 order) and JS number formatting; that is fine while JL-14 stays in Node, and the doc should say the key is Node-computed only. Godot's JSON parser returns all numbers as float; `Number.isInteger`-style "whole number" checks in the doc are value-based, so no semantic drift there.

5. **Determinism leak paths.** Closed event field sets (`protocol.mjs:415-430`) and the `events-wall-clock.ndjson` fixture cover events. Two open surfaces remain: (a) `sim` is open (`PROTOCOL.md:42`, `protocol.mjs:295-306`) so a wall-clock key in `sim` passes despite `PROTOCOL.md:11`; harmless because `sim` is in neither hash, but the doc should say "unchecked and never hashed" rather than imply enforcement. (b) `state.stage.time_s` is described as "whole seconds" (`PROTOCOL.md:145`) without saying it is tick-derived; if JL-09 computes it from wall time it enters the verdict-cache key. Fixtures are consistent with `floor(tick / tick_hz)` (`state-000001.json:16` tick 90 → 1; `state-evade.json:16` tick 360 → 4). One line in the doc would close it.

6. **Missing invalid fixtures / trial-level negatives.** Validator rules with no fixture or unit test: wrong `protocol` string (`protocol.mjs:73`); intent for a seq never snapshotted (`:566-571`); non-contiguous snapshots (`:543-548`); `done.snapshots` mismatch (`:629-634`); `trace_hash` mismatch at trial level (`:641-649`, only the short-hash format case exists); `done.json` beside `error.json` (`:587-589`); `aborted` without `abort.json` (`:635-640`); `intent_timeout` tick mismatch (`:673-678`). Duplicate seq is impossible by file name; out-of-order state ticks are caught by `:555-560` but untested. DoD 3 only requires one invalid per message type, so this is a note; JL-11 will lean on `validateTrial`, so I recommend the trial-level negatives land before or with JL-11.

7. **`validateTrial` accepts `state-(n+1)` with no `intent-n`.** `protocol.mjs:576-585` computes expected `held` as `null` when the prior intent file is absent, so a directory with state-000001 and no intent-000000 passes if `held` is null. Under the protocol Godot cannot reach seq 1 without intent 0, so this is a missed invariant, not a false rejection.

8. **Watchdog wording.** `PROTOCOL.md:115` ("No new Godot file within …") reads as if Jev latency counts; `:119` defines a step from Node's intent rename to the next Godot file, which excludes it. Make `:115` say "after Node's last intent" so JL-11 does not start the timer during a live call. Formula itself is correct: `protocol.mjs:750` (`sorted[ceil(n/2)-1]`) matches `scripts/lab/stats.mjs:51` nearest-rank; tests at `protocol.test.js:298-303` check odd, even and floor cases.

9. **No abort reason for Node-side `invalid`.** `PROTOCOL.md:117` says Node "stops reading"; with `ABORT_REASONS` closed to `interrupted|arm_error|replay_miss` (`protocol.mjs:31`) Godot would block 30 s and exit 5. Either JL-11 writes `abort{arm_error}` (a stretch) or v2 adds a reason; note for the JL-11 card. Related: on a crash, `events.ndjson.tmp` is the only trace and readers ignore `*.tmp` (`:8`); JL-11 may want to keep it for diagnostics without validating it.

10. **Test tightness (style).** `protocol.test.js:84-89` and `:141-145` assert `some(error.path === entry.path)`, not that the fixture fails for exactly that reason. I hand-traced all 17 invalid fixtures and the late-intent trial; each yields exactly one error (e.g. `intent-single-not-forced.json` against state-000001: `ram_target` kept, `hit_kicker` dropped at 17.5 < 26, so only the `source` error; `trial-late-intent`: only `events[19].tick`, since the applied-set check at `:650-661` is satisfied). Tightening to `deepEqual(paths, [entry.path])` would lock that in.
