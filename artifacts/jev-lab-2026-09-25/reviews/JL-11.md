### Findings (none blocking)

**N1: A capped batch hides a crash.** `harness.mjs:469-475` checks in the order invalid, then capped (inconclusive), then any non-complete (fail). If trial 0 crashes and trial 1 hits the cap, the batch reports `inconclusive`. In JL-12's gate, `inconclusive` maps to exit 3 (`JL-coord/scripts/lab/gate.mjs:17-22,152-157`). The harness never emits the `engine_crash` sentinel (`metrics/core.mjs:159-166`), so the batch result is the only place a crash shows up. The plan makes sentinels red on a single occurrence (`plan.md:155`), so a crash is a conclusive signal and should not be hidden by a small sample.
- Fix (JL-12/JL-17): put crash/stall/error ahead of capped, or emit `engine_crash` per batch.

**N2: `arm_error` aborts land in the same bucket as engine failures.** Any `aborted` trial gives batch `fail`, which is gate exit 1 ("conclusive regression"). In JL-14 a Jev API failure would therefore read as a gameplay regression rather than exit 3 or 4.
- The per-trial entry separates some causes: `outcome` is `invalid` for a rejected Godot file, and `config.capped` marks the cap.
- An arm throw and an invalid intent differ only in the `abort.message` text (`harness.mjs:263-288`).
- `trial_abort_rate` counts every non-complete trial (`:448-456`), so harness faults and instrument faults cannot be separated.
- Using `arm_error` itself is acceptable: the list is closed (`protocol.mjs:31`) and the choice is documented (`harness.mjs:11-18`).
- Fix: add a structured Node-side field such as `entry.abort.cause` (`node_invalid | arm_throw | intent_invalid | call_cap`). It lives in the run record, not the protocol, so the closed list is untouched. Feed `api_error_rate` from it in JL-14.

**N3: No cleanup of child processes if the harness itself dies.** The three new files contain no `process.on(...)` handlers (grep found none). The `finally` at `harness.mjs:327-332` kills the child only when `runTrial` throws.
- If the harness gets SIGTERM, a `--stall-at` fake is orphaned forever (`fake-godot.mjs:251-253`). A normal fake exits after its 30 s intent timeout.
- Ctrl-C at a terminal reaches the whole foreground process group, so it is less exposed.
- The harness never writes `abort{interrupted}` on SIGINT.
- SIGKILL goes to the direct child only (`:192`). A Godot started through a wrapper would leave the real Godot process running.
- Fix for JL-17: spawn with `detached: true` and `process.kill(-pid, "SIGKILL")`, plus SIGINT/SIGTERM handlers that write `abort{interrupted}`.

**N4: A malformed `done.json` or `error.json` throws instead of recording `invalid`.** `harness.mjs:346` and `:348` call `JSON.parse` without a guard, after `validateTrial` has already flagged the file.
- `runBatch` then throws before `run.finish`, which leaves a claimed run directory with no record.
- The fake cannot trigger this because it writes files atomically (tmp then rename). A real Godot could, which would break DoD 1 ("one record per batch") in JL-17.
- Fix: guard both parses and fall through to `invalid`.

**N5: The launch seam is enough for flags, but D/k are missing.** `launch({io, scenario, seed, trial}) -> {command, args}` (`harness.mjs:162`) is a closure, so JL-17 can put `--headless --fixed-fps 90 --path … --script …` and user args in it.
- The spawn takes no `env` or `cwd` (`:163`).
- The harness has no D/k (`snapshot_every`/`hold_ticks`) config, the record does not store them, and hello's timing is not checked against the requested values. Only the scenario is cross-checked (`:227-229`).
- JL-21's sweep (D ∈ {45, 90}, k ∈ {0, 26, 54}, `plan.md:136`) needs all three.
- `fakeGodot()` always uses `TIMING` (`fake-godot.mjs:194`).

**N6: Consecutive batch seeds reuse most trial seeds.** Each trial's seed is `seed + trial` (`harness.mjs:418`), so batch seed 1 and batch seed 2 share 19 of 20 random-arm trial seeds. Comparisons across batches are then not independent. Document this, or space seeds as `seed * N + trial`.

- The mutation receipt `02-mutations.txt:1` is stamped `cd06534 (uncommitted candidate)`, not aa4856d. Only M2 and M7 were rerun after the test file changed (`:9-11`).
