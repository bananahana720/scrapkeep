2. **By the card's design, the tagger can only confirm existing labels.**

   - The writer implemented the card faithfully. But the plan's "Fills the verdict tags; powers agent_agreement" (plan.md:211) cannot scale to entry 3 and later without hand-labelling each one.
   - This is a contract question for a later card, not a defect in this attempt.

   - The plan also asks for "a labelled corpus plus a blind set, with severity weights" (plan.md:201). JL-20 has only the control, because the card's DoD narrowed it. Record this as a scope gap, not as a failure of the DoD.

4. **The gate-isolation test only looks one level deep.**

   - Isolation does hold today. Searching the whole repo, excluding `artifacts/`, finds `verdict-tags` imported only by its own test.

   - A future indirect import would pass this test.

5. **The cross-run call cap undercounts failed calls.**

   - A non-OK response throws at `:249-252`, before the log line is appended at `:255`. A fetch rejection is also never logged.
   - As a result, failed calls do not count toward the 20-call cap across runs. Within a single run, `run.calls` does count them (`:150`).

6. **Minor robustness issues.**
