## 1. What reviews caught that writers missed

- **Computed numbers presented as measured (overclaim).** JL-00 audit (Fable, TRACKING.md:786/EV-0485; audit/README.md:46-75) found "~7.7 s per boot" was a code comment with no timing artifact, and a results table "unchanged since 9c067de... despite 're-scored after every change'" (stale, not re-measured). Caught by the Fable consequential audit, not the routine reviewer. Portable.
- **Simulated-vs-measured, same failure recurred twice.** JL-06-A1 FAIL (Opus routine review, TRACKING.md:802/EV-0501): suite records were timestamped after the suite ran, so a "measured" start time was sampled at the end; CONTRIBUTING carried a computed "~7.7 s" against a measured 3.6 s. JL-23-A1 FAIL (TRACKING.md:846/EV-0545): "the first-failure seconds were simulated for a runner that does not exist." Both caught by Opus medium review. Portable rule: a reviewer must trace whether a reported time comes from a running clock around the real operation, not from a post-hoc estimate.
- **Undisclosed cherry-picking.** JL-23-A2 FAIL (TRACKING.md:850/EV-0549): four measured mutations were reported without disclosing their selection; one was added by the writer *after* seeing its simulated result. Caught by Opus medium review, which required the coordinator to pre-name the mutations before any further measurement. Portable — pre-registration-style discipline.
- **Blind-set leakage via option wording (text-only-rule gaming).** JL-04-A2 FAIL (TRACKING.md:797/EV-0496): five dodge options literally named the telegraph, so a text-only rule scored 5/5 without reading game state; the writer's own neutrality scan had no pattern for it. Caught by Opus medium review held blind to the prompt side. Scrapkeep-specific mechanics, portable principle (a labelled corpus must be checked against a trivial baseline rule, not just against domain correctness).
- **Result-triggered relabelling / prompt tuning after seeing output.** JL-19 changes_requested (TRACKING.md:833/EV-0532): "the rerun Noul wording was changed after one probe call on an authored case and before any blind scoring" — a correction that was directionally right but result-triggered, so it had to be re-scored from a frozen cache with zero new calls. Same pattern in the JL-00 audit's finding 4: an adversarial case's label was changed by the prompt's own author in the same commit that produced the pass (audit/README.md:16). Portable: any post-hoc edit made after seeing a result, even a defensible one, invalidates that result and must be redone blind.
- **Missing disclosure of secrets exposure.** JL-19 review (TRACKING.md:833/EV-0532) found four redaction gaps (lowercase `bearer`, JSON-quoted secrets, a second home path after a colon, the resolved key in score mode) before any log text was allowed to leave the machine — caught by Opus medium review, verified directly by the coordinator probing `redact()` (TRACKING.md:835/EV-0534).
- **Stale/dirty-tree evidence.** JL-21 (TRACKING.md:847/EV-0546): Fable review conditioned admission on a re-run at clean head because the original batches ran against a dirty tree at the base commit; the coordinator independently reran and matched trace hashes 20/20. JL-18b (TRACKING.md:837/EV-0536): Fable flagged that the live blind run was made on a commit with uncommitted edits; coordinator confirmed the diff scope and retained `tree-at-run.txt`. Portable, high-value rule: "ran on head X" claims need the actual tree state (clean/dirty) recorded, not just the SHA.
- **Fabricated instrument claims (deepest catch).** JL-00 audit (Fable) retracted: a sweep conclusion contradicted by its own retained artifact (6/15 "taken" under the code's own rule, not the claimed 4/15); a "negative control" that existed only as prose with no code path; and an adversarial 4/4 score that depended on a same-session relabel (real score 3/4 on original labels) — audit/README.md:13-17. This is the single largest catch in the program and only the Fable audit found it; the routine Opus reviews in later waves caught mechanical/procedural violations, not fabricated evidence at this depth. **Review-tier pattern: Fable review is where recomputation-from-raw-artifact and instrument-validity catches happened; Opus routine review is where contract/DoD and mechanical-bug catches happened.**
