# Per-project summaries

**1. ethanhinson/jevdoom** — https://github.com/ethanhinson/jevdoom — **License: none found** (LICENSE 404 → default all-rights-reserved; ideas only, no code copying).
Three linked sketches sharing one decision pattern: **jevdoom** (ViZDoom) — "Jev picks which enemy to deal with and whether to fight, hold, retreat or grab a pickup; code turns that into button presses." **jevtetris** — code enumerates every reachable placement and the resulting board; Jev picks one (candidate-generation + single-Choice pattern). **jevgameboy** — same decision core, reads real Game Boy Tetris off PyBoy screen tiles. Companion tool **jeview** (`../jeview`) "sits between this code and TypeSafe, records every call, and draws them on a live map" — a decision-telemetry visualizer, but its own repo 404'd so I could not confirm its UI contents directly; treat as unverified. JSONL logging of every Jev call to `logs/`.

**2. mikespins/doom-jev** — https://github.com/mikespins/doom-jev — **License: none found** (404; ideas only).
Three-process shared-memory architecture: `game.py` (ViZDoom ASYNC_PLAYER, 35 tics/s, non-blocking), `brain.py` (queries every 120ms), `ui.py` (pygame HUD). Single Choice question, 6 actions (`turn_left/turn_right/move_forward/move_back/shoot/use_open_door`), temperature-sampled (default 0.3), max 5 concurrent requests, capped 1,100/min. `perception.py` builds a 7-field ordered text description (status → damage trend → enemies → items → environment → nav → stuck-state). Enemies use **screen-relative position words** (far left/left/center/right/far right, thresholds at cx 0.2/0.4/0.6/0.8) plus a 4-bucket categorical distance (very close <150, close 150-400, medium 400-800, far >800) — a screen-space quantization distinct from the polar-bearing approach below. Two hardcoded reflex overrides (auto-shoot in a ~5%-of-screen center cone within 400 units; wall-stop within ~48 units via depth buffer) — Jev never controls collision safety. Logs every decision to `logs/decisions-*.jsonl` with prob/latency/applied-or-dropped-stale flag. Measured: 35 tics/s game, ~8 decisions/s, median latency ~120ms on a 1-vCPU VM.

**3. olivier-motium/jev-doom** — https://github.com/olivier-motium/jev-doom — **License: MIT.**
Freedoom via ViZDoom, two providers (TypeSafe direct or Vercel AI Gateway). "observable" mode sends structured engine data (visible entity id/position, viewed floor/wall cells, remembered observations **with ages** — an explicit memory-decay/staleness field); "assisted" mode adds scripted tactical support. `tactics.py::build_menu()` builds up to 7 labeled options (label + kind + controls + predicted outcome), **sorted deterministically by `(priority, route_units)` with no randomization** — the repo itself effectively concedes a position-bias risk it never measures or corrects. An 8th `observe` option auto-appends as a fallback when predictions were wrong, damage was unexplained, or nothing new appeared. **Budget control is the strongest of any repo reviewed**: $15 cumulative charged-or-reserved cap across both providers, $0.05 reserved per request, persisted in `runs/budget.json` across restarts, configurable via `JEV_BUDGET_USD`. Dashboard at `127.0.0.1:8767`, polls `/api/state` every 350ms: MJPEG game stream, per-channel decisions (FACE/MOVE/TRIGGER/WEAPON), top-5 probability bars, telemetry (last/avg/p95 latency, call count, reported cost, latency sparkline), automap (walls, player position+heading, movement trail, objective marker), a **standing-orders textbox** for live mid-run instruction injection plus a one-click "Dodge" preset, and pause/resume/stop/restart-same-seed controls.

**4. tirukovelamanoj/jev-plays-doom** — https://github.com/tirukovelamanoj/jev-plays-doom — **License: MIT.**
No visual input — pure structured JSON (`health`, `ammo`, `facing_deg`, `monsters_nearest_first` with kind/distance/bearing). Only project with an **explicit, documented sign convention**: "bearing 0 = dead ahead. POSITIVE bearing means the monster is to your LEFT... NEGATIVE means to your RIGHT," computed as `(atan2(dy,dx) - ang + 540) % 360 - 180`, both rounded to integers. Smallest action space of any project: 3 buttons (`ATTACK/TURN_LEFT/TURN_RIGHT`). Model pinned only as the alias `"jev-latest"`. Has a **confidence-floor fallback**: below `conf_floor`, "trust the geometry instead of a coin flip" and use a hand-coded heuristic instead, tracking a `low_conf` counter. This is the **only project with a real evaluation**: `defend_the_center` scenario, 20 episodes, seed 1234, Jev tied a hand-coded heuristic baseline at 6.55 kills/episode (131 total across both). 2,642 calls logged, latency flat at 212ms, mean confidence 0.88.

**5. AmoghCreator/doom-jev** — https://github.com/AmoghCreator/doom-jev — **License: MIT.**
Fully decoupled async design: game loop 35 tics/s continuous, inference loop ~10Hz; between inferences, a `composition_dag.py` maintains smooth actuation via trig-based geometric tracking rather than holding a stale intent verbatim. **Richest per-tick decomposition found**: 6 Jev questions per tick — 4 Choice (`macro_goal`: engage/collect_weapon/explore/flee; `target`: enemy-or-none; `movement`: 5 options; `rotation`: 3 options) + 2 Noul (`jump`, `firing`) — directly matching the lab's own Choice/Noul framing. Hybrid execution: Jev's macro decision is merged with trigonometric aim-lock ("zero-hesitation trigger lock" fires within ~15° of crosshair or above a confidence threshold). Terminal HUD: confidence-color-coded, 8-channel action indicator, live standing-order injection. **No budget/cache control found** — only a 1.5s httpx timeout per request; this is a gap relative to olivier-motium.

**6. lukaske/jev-doom-agent** — https://github.com/lukaske/jev-doom-agent — **License: mixed/unclear.** Chocolate Doom itself is GPL-2.0-or-later, Freedoom assets are BSD; the repo's own bridge/UI code license was not confirmed (treat as all-rights-reserved by default — ideas only).
Runs two isolated Chocolate-Doom-to-WASM instances on the same Freedoom map. `browser_doom_bridge.c` exposes health/armor/ammo/damage/coordinates/kills/line-of-sight monsters/visible pickups to JS; server POSTs this plus a typed Choice question to `https://api.typesafe.ai/v1/systemone`, model `"jev-latest"`. **Notable, borrowable discipline**: the response is validated for `choice`/`probabilities`/`confidence`, and a failed or low-confidence call is **visibly labeled `FALLBACK`**; a fully offline mode is permanently labeled **"OFFLINE SIMULATED POLICY — NOT JEV"** — an explicit anti-fabrication convention so a viewer never mistakes scripted behavior for the model's. API key kept only in server process memory, never logged/persisted, cleared on disconnect/page close.

**7. BunsDev/typesafe-ai-playground PR #6** — https://github.com/BunsDev/typesafe-ai-playground/pull/6 — **License: not checked (repo license unconfirmed) — ideas only until verified.**

Evaluated against human play and a **seeded-random control**, with session scoreboards. # Cross-project patterns

- **Universal decomposition**: every project has Jev choose intent/target/macro-goal at a coarse grain; deterministic or trig-based code handles aiming, movement execution, and collision/wall safety. No project gives Jev raw pixels or frame-level control.
- **State framing splits two ways**: screen-space quantization (mikespins: 5 position buckets × 4 distance buckets) vs. world-space polar bearing+distance with an explicit signed convention (tirukovelamanoj, AmoghCreator's composition_dag). The signed-bearing convention is the more rigorous, less ambiguous approach.
- **Cadence convergence, but non-blocking**: decisions land at ~8-10Hz / ~100-212ms across mikespins, AmoghCreator, lukaske, tirukovelamanoj, tied loosely to Doom's 35-tic engine rate — but in every case **the game keeps running during the roundtrip** (async loop, hold-last-intent, or geometric interpolation of the last decision). None blocks the physics step to wait for a verdict.
- **Position bias is structurally present but never measured**: olivier-motium's deterministic priority-sort with zero randomization is a self-admitted, uncorrected bias risk; no project in this set reports measuring position bias the way the lab did.
- **Confidence-floor fallback is a recurring, independently-invented pattern**: tirukovelamanoj's `conf_floor`, AmoghCreator's trigger-lock confidence threshold, and lukaske's `FALLBACK`/`OFFLINE SIMULATED POLICY` labeling all converge on "below a confidence bar, use named deterministic code and say so."
- **Model pinning is mostly by alias, not resolved version**: `"jev-latest"` appears in tirukovelamanoj, AmoghCreator, and lukaske; only mikespins uses a dotted literal (`"jev-1.13.0"`), which is still an unverified free-text constant, not a resolved build id.
- **Evaluation is generally weak**: only tirukovelamanoj names a scenario, seed, episode count, and baseline (tied a hand-coded heuristic, single seed). BunsDev's playground compares to seeded-random but is mock-driven and access-blocked live. Everyone else reports throughput/latency, not skill.
- **Cost control is uneven**: olivier-motium is the only project with a persisted dollar cap; AmoghCreator has none beyond a request timeout; the rest rely only on call-rate caps.
- **Watch-UI convergence**: probability bars, latency percentiles, per-channel decision breakdown, automap/trail view, and a live text-box for mid-run human steering recur across the two most complete UIs (olivier-motium, AmoghCreator terminal HUD).

# Ideas to borrow for a Godot watch view (JL-31), prioritized

1. **[High] Explicit FALLBACK/non-Jev labeling** (lukaske) — any time cache, timeout, or low confidence substitutes scripted behavior, the watch view must say so on-screen, never silently presenting it as a Jev decision. Directly protects against the lab's own verdict-cache alias/version risk becoming invisible to a viewer.
2. **[High] Standing-orders textbox with live injection + one-click presets** (olivier-motium's "Dodge" button) — cheap to build in Godot, gives Andrew an interactive probe without restarting, and doubles as a capture point for JL-30's lesson corpus (the moment a human overrides Jev is itself a labeled training example).
3. **[High] Per-channel decision breakdown with top-N probability bars, not one aggregate number** (olivier-motium's FACE/MOVE/TRIGGER/WEAPON panel; AmoghCreator's 8-channel indicator) — makes position/framing bias visible live, on the same axis the lab already measures.
4. **[High] Latency/cost telemetry panel** (last/avg/p95 ms, call count, reported cost, sparkline) — cheap, keeps cadence and budget visible during a watch session; matches both the lab's 1Hz-cadence finding and the missing-budget-control gap seen in most of these projects.
5. **[Medium] Automap/trail view** (walls, player position+heading, movement trail, objective marker) — natural fit since Godot already renders 2D top-down for the orchard sketches; reuse the same rendering path.
6. **[Medium] Confidence-color-coding tied to whatever confidence-floor fallback the lab adopts** (AmoghCreator) — visually links the Choice/Noul confidence number to the fallback behavior from idea #1.
7. **[Low/optional] Live game-view streaming alongside the decision panel** — only worth doing once the Godot sketch has a stable render target; every Doom project streams video, but it's the most expensive piece to build and least differentiated for a "watch a decision, not a game" use case.

# Ideas for the skill suite (JL-30)

1. **Decomposition checklist**: require naming, for every tick, the smallest set of orthogonal Choice/Noul/Score questions, and an explicit check of whether a single multi-option Choice could be replaced by independent per-option Nouls to cut position bias — generalizes the lab's own 0.35-vs-0.02 bias gap and AmoghCreator's real (if not bias-motivated) move toward parallel Choice+Noul decomposition.
2. **Framing/dominance audit step**: require a documented dominance-control option (a "free, correct, no-cost" choice) in every menu-style Choice before trusting its live ranking, modeled directly on the lab's own take-a-free-cache test and consistent with the awesome-list's stated limit ("accuracy drops with irrelevant state," "reads literally"). No prior-art project runs this control — it's a real gap the lab is ahead on, not behind.
3. **Model-pinning rule**: resolve alias → specific version at verdict-cache write time, not just at call time. Four of six code-inspected repos use `"jev-latest"` as a bare alias; this generalizes the lab's own flagged cache risk into a concrete build step.
4. **Confidence-floor fallback pattern** as a reusable component: below a stated threshold, fall back to named deterministic code and label the output as non-model (lukaske's `FALLBACK` convention, tirukovelamanoj's `conf_floor`, AmoghCreator's trigger-lock threshold).
5. **Evaluation-baseline requirement**: no "plays well" claim ships without a named scenario, seed, episode count, and a stated baseline (scripted or random) — tirukovelamanoj is the only prior-art example that does this correctly, and both it and the Medium source's own caveat ("a scripted bot would beat it") argue for treating scripted baselines as fragile and needing their own verification, which directly echoes the lab's scripted-ladder-beaten-by-random defect.
6. **Budget-cap-with-persistence template**: olivier-motium's $15 cumulative cap, $0.05 per-request reserve, and `runs/budget.json` persistence across restarts is the most complete cost-control pattern found and is directly portable as a skill-suite reference implementation.

# Agreements / disagreements with the lab's findings

- **Position bias**: no prior-art project measures this directly, but the mechanism is structurally consistent — olivier-motium's fixed, non-randomized menu ordering is a self-admitted, unaddressed bias risk, and the two most decomposed designs (AmoghCreator, tirukovelamanoj) lean toward independent Choice/Noul channels rather than one big menu. This is consistent with, but does not confirm, the lab's 0.35-vs-≤0.02 result — inferred, not verified by any source.
- **Framing/dominance failure**: the awesome-list's stated limit ("reads literally... accuracy drops with irrelevant state") agrees qualitatively with the lab's dominance-control failure (P(take) 0.38-0.56 on a free-cache option), but no prior-art project ran anything resembling a dominance test. This looks like a genuine lab contribution prior art hasn't attempted.
- **Cadence and blocking**: this is the clearest **disagreement**. The lab's own architecture blocks the physics step for the full roundtrip (1Hz, 90-tick snapshot, 26-tick-delayed intent applied). Every Doom project reviewed here keeps the game running during the wait — async loops, hold-last-intent, or geometric interpolation — at a faster effective cadence (~8-10Hz). This is concrete and actionable: prior art's non-blocking pattern is directly borrowable to remove the lab's physics-step stall for JL-31.
- **Scripted baselines are fragile**: the lab's scripted ladder policy losing to random "due to a scenario defect" is echoed by two independent signals — tirukovelamanoj's Jev-ties-heuristic result (a baseline strong enough to tie, not obviously broken) and the Medium article's own caveat that a scripted bot would beat Jev at Doom. Neither source discusses baseline fragility explicitly, but both converge with the lab on treating "verify the baseline itself isn't broken" as a precondition for trusting any comparison.
- **Model-pinning / cache-alias risk**: the lab is ahead of, not behind, prior art here. Four of six code-inspected repos pin by bare alias (`jev-latest`); none resolves alias-to-version at cache-write time. This confirms the lab's flagged risk is real and widespread, and that no example implementation has solved it yet.
- **"Jev is parked as a player in this lab"**: no direct comparant, but BunsDev's playground PR independently arrived at the same practical stance for a different reason — its live Doom path is blocked by HTTP 402 (billing/access), so its own evidence is mock-only and it does not claim a working live player either. Different cause (defect vs. access), same "not yet trustworthy" conclusion.
