### Warning system

Source: https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/static_typing.html

Godot features a warning system that flags potential runtime issues as you write code. Warnings specific to typed GDScript are disabled by default and can be enabled under Project Settings (Debug > GDScript with Advanced Settings enabled), including UNTYPED_DECLARATION to enforce static typing, INFERRED_DECLARATION, and UNSAFE_* warnings.

### GDScript warning system

Source: https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/warning_system.html

The GDScript warning system complements static typing to help detect mistakes during development that may lead to runtime errors. Warnings can be configured in Project Settings under the GDScript section, which is visible when Advanced Settings is enabled. While warnings do not prevent the game from running by default, individual warnings can be configured to act as errors to block compilation until resolved.

### Retrieve User-Defined Command-Line Arguments in GDScript

Source: https://docs.godotengine.org/en/4.7/classes/class_os.html

Distinguishes general engine command-line arguments from custom user arguments passed after the double dash delimiter (--).

```gdscript
# Godot has been executed with the following command:
# godot --fullscreen --custom -- --level=2 --hardcore

OS.get_cmdline_args()      # Returns ["--custom"]
OS.get_cmdline_user_args() # Returns ["--level=2", "--hardcore"]

```

### Retrieve Command-Line Arguments in GDScript

Source: https://docs.godotengine.org/en/4.7/classes/class_os.html

Returns custom command-line arguments passed to the engine. Arguments handled directly by the engine (such as --headless) are excluded from the returned array.

```gdscript
# Godot has been executed with the following command:
# godot --headless --verbose --scene my_scene.tscn --custom
OS.get_cmdline_args() # Returns ["--scene", "my_scene.tscn", "--custom"]

```

### Define a Standalone Script in GDScript

Source: https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html

Scripts executed from the command line must inherit from SceneTree or MainLoop. Call quit() when processing finishes to exit the engine process.

```gdscript
#!/usr/bin/env -S godot -s
extends SceneTree

func _init():
    print("Hello!")
    quit()

```

### Handling quit requests > Sending your own quit notification

Source: https://docs.godotengine.org/en/4.7/tutorials/inputs/handling_quit_requests.html

Forcibly closing the application via SceneTree.quit will not send NOTIFICATION_WM_CLOSE_REQUEST to nodes, preventing custom cleanup actions like saving or confirmation dialogues. To notify nodes in the scene tree about an upcoming termination, manually propagate the notification; this notifies nodes without automatically terminating the program, requiring an explicit SceneTree.quit call afterward.
