### bool can_process() const

Source: https://docs.godotengine.org/en/4.7/classes/class_node.html

Checks if the node can receive processing notifications and input callbacks from the SceneTree and Viewport based on its process_mode and tree state.

```APIDOC
## can_process

### Signature
`bool can_process() const`

### Description
Returns `true` if the node can receive processing notifications and input callbacks (`NOTIFICATION_PROCESS`, `_input()`, etc.) from the `SceneTree` and `Viewport`.

### Return Value
- **bool** - Returns `true` or `false` based on `process_mode` and `SceneTree` state:
  - `PROCESS_MODE_PAUSABLE`: returns `true` when the game is processing (`SceneTree.paused` is `false`).
  - `PROCESS_MODE_WHEN_PAUSED`: returns `true` when the game is paused (`SceneTree.paused` is `true`).
  - `PROCESS_MODE_ALWAYS`: always returns `true`.
  - `PROCESS_MODE_DISABLED`: always returns `false`.
  - `PROCESS_MODE_INHERIT`: uses the parent node's `process_mode` to determine the result.
  - If the node is not inside the tree, always returns `false` regardless of `process_mode`.
```

### Handling quit requests > Sending your own quit notification

Source: https://docs.godotengine.org/en/4.7/tutorials/inputs/handling_quit_requests.html

Forcibly closing the application via SceneTree.quit will not send NOTIFICATION_WM_CLOSE_REQUEST to nodes, preventing custom cleanup actions like saving or confirmation dialogues. To notify nodes in the scene tree about an upcoming termination, manually propagate the notification; this notifies nodes without automatically terminating the program, requiring an explicit SceneTree.quit call afterward.

### SceneTreeTimer > Description

Source: https://docs.godotengine.org/en/4.7/classes/class_scenetreetimer.html

SceneTreeTimer is a one-shot timer managed by the scene tree that emits a timeout signal upon completion. Unlike a standard Timer, it does not require instantiating a node and is dereferenced automatically after its time elapses unless a reference is retained. The timer is processed after all nodes in the current frame have completed their process or physics process steps.
