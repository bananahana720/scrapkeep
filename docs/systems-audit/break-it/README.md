# Break it: world 1 (systems audit pass F)

**Result.** Twenty-four bot runs tried to break world 1 on the park maps, and none of them broke it. They mashed every input the ball reads. They quit and continued in the Warden fight, at the open gates, in Brindle's arena and mid-stage. They stacked a big build with a curse and low hull. No run crashed, logged a script error, soft-locked, let a number escape or broke the save file. One finding is high enough to fix, and it is a Blocker: a cleared stage is not saved until the next stage is entered, so a quit or crash in between loses it (F1). That gap is 5 to 100 s after the dam in these runs, where it covers only the gates and the launch. After the flume it also covers the whole Brindle fight, because a world boss is not a stage entrance: a quit 20 s into Brindle continued at the start of the flume, without the flume's cogs and part. The fix belongs in `flow.gd`. It now has its own thread, "Keep a cleared stage's earnings on Continue", and the boss case goes first. **Update, 12 Nov:** the fix is PR 790 (head 85461fc8), stacked on `stage/alpha-w37` at 5159ce67. It saves the run at the launch and before the boss arena. Measured on both the PR head and the stage, a quit in the launch or in Brindle's fight now keeps the stage's earnings. A quit at the open gates still replays the stage from its start, by design, so the stage's loot is never paid twice; that case is now a Minor row (F5). Three smaller findings are backlog rows. The bots' input mash cannot finish the dam Warden's spillway-sheet fight, but that is a weakness of the bot's hands, not of the game.

**Card.** SA-F in [BACKLOG.md](../../../BACKLOG.md#sa-f-break-it-world-1). It was read at `stage/alpha-w37` 5268fe06 and written at bcccc24f. The runs used the 4-core cloud box with `--bot-no-visuals=1`, which plays the same ticks (PR 784, the speed-up of test and bot runs).

**Severity.** This page uses the [alpha bug bar](../../../sketches/core-loop/BUG-BAR.md). The card says "high and above"; the bar has no "high", so this page reads it as Blocker and Major.

## How it was attacked

The tool is [`tools/sysaudit/break_run.gd`](../../../sketches/core-loop/tools/sysaudit/break_run.gd). It wraps `bot_run.gd`, so the run and its `bots.ndjson` row are the normal bot's, with `--qa-log=1` for the play watch (stuck, hung, wedged, fell). Every attack is seeded, so the same command replays a run tick for tick (checked once: seed 2880 gave the same stall and the same hung row twice). A row carries the seed and the mode; the rest of the command is in the run's line in `runs.json` and the rerun section below. The tool's header lists each watch row and flag; the page does not repeat it. The policies are the existing bots: the skipper takes the fastest line, the completionist takes every side spot first, and random is the first-timer.

| Attack | `--break=` | What it does |
| --- | --- | --- |
| Input spam | `spam` | On top of the bot's own input, presses each play input the ball reads about three times a second: jump, the go verb (Sable's boost, Rivet's sprint, Kest's blink), interact, fire, harpoon press and release, cancel, slot picks, the ultimate and the racked active. It also adds short holds with their releases, a random stick now and then, and the pause toggle (the P key) pressed and lifted a few ticks later. It keeps mashing through launches, the gates and the boss, so an input taken in the wrong state shows up. This is the bot that presses boost which pass C asked for. |
| Sequence breaks | `spam` | The same mash in every flow state, with the skipper (fastest line) and the random first-timer. |
| Save-and-quit | `quit` | Frees the game with no save, as a closed window or a crash does, and continues through the title's Continue (`flow.resume_run`) in a fresh game. `--quit-in=<state>:<s>` aims the quit at a state: `beacon` (the Warden fight), `gates` (after the break), `launch` or `boss`. The saved entrance is the run file the game writes as each stage starts. The check is that the continued run matches it (stage, cogs, parts, cores, the death save and hull), never holds more than at the quit, and does not restart a stage the quit came after clearing. After a death or the summary, Continue must be refused. |
| Buffs with debuffs | `stack` | A random legal build of 6 to 14 parts (item fuzz's draft), a curse deal taken, scrap wear on (the default), the hull set to 15% at every new stage, and the run seed's own stage modifiers. |

A watch checks every tick for softlocks, unkillable states, out of bounds and escaping numbers, and writes `break-<seed>.ndjson`; the tool's header lists its rows and limits.

**What did not break** (every run, `runs.json`):
- No crash, script error or engine error in 24 runs.
- No non-finite number, hull over max, hull at zero without a death, speed over 200 m/s (93 m/s in the runs that stayed in world 1; the one run that went on into world 2 peaked at 97 m/s), fall out of the world, negative resource, flow stuck outside play, or pause left on.
- Continue always matched the saved run file and never held more than at the quit: 10 quits, in the Warden fight, at the gates, in the launch, in Brindle's arena and mid-stage. The quits before a clear (in the Warden fight and mid-stage) lost only what the Bible says rolls back.
- After a planted death (`--plant=damage=25`, seed 2885), Continue was refused. The store code then leaves an "ended run" marker, so no older copy can be continued (`run_store.gd` `clear`); the tool checks only that Continue was refused.
- Mashing with the pause toggle never left the game paused and never broke a stage or the dam Warden's gates. That holds for every spam run in the dam. After the dam it rests on one run: spam seed 2874 mashed through both sets of gates, both launches, the flume and Brindle, and beat him. The other spam runs stalled at the dam Warden (see the notes).

**Not tested:**
- A spent death save across a quit. No run earned one. `run_save_interrupt_test` covers the spent flag on disk.
- Moss's counter while mashing. The bots never shop. The sell price is pinned to the price paid (`shop.gd` `sell_quote`, after the w24 and 8 Nov red-team catches), and the scale only pays for scrap carried, which has no free source. A loop there would need a shop-pressing bot.
- The screen keys (title, pilot select, cards, the death and summary screens, Esc), the pause menu and holding the notes open. A test-mode game ignores key events, so the mash reaches only what the ball reads plus the pause toggle.
- Pads, frame times and anything a person feels.

**Notes that are not game bugs:**
- The bot's hands under spam. Four of five skipper and random runs stalled at the dam Warden. All four that were rerun with the mash stopped at a set second (`--spam-until`) broke the Warden within about 25 s of the stop. The game was not left broken: the mash ruins the bot's timed hook release on the spillway sheet.
- The stacked build ended world 1 with 2,852 cogs (seed 2879), against 1,302 to 2,223 for the other runs that cleared world 1. Both stacked runs that reached the flume's break were paid about 480 cogs and 480 scrap in one second there. The one stacked run that went on into world 2 logged four more such jumps there (the tool keeps three rows of a kind, so only one of those four has a row: stage 3, in the Warden fight). These are bigger payouts, not a loop. Pass B's prices own it ([economy/](../economy/README.md)).
- Low hull did not last. A hull set to 15% at each stage start healed before the first fight: the lowest hull in a stacked run was 17 of 140. (The first two stacked runs set it from stage 2 on, because the tool missed stage 1; seed 2886 sets it from stage 1.) This is pass A's hull-regen finding ([systems-map.md](../systems-map.md)), not a new one.

## Change request for the coordinator

ORCHESTRATOR owns the tiered gate, so this is a request, not an edit. At each sprint close, run pass F's break bot together with pass B's balance sim, one seed per process, on 4 cores, about 10 minutes a run:
- three quit runs per world, aimed at `gates:3`, `launch:0.3` and `boss:20`;
- one stack run;
- one spam run with `--spam-until` set past the first Warden. A full-mash run usually stalls at the dam Warden, because the mash spoils the bot's timing, and would test only the dam.

Reopen the sprint if they find a new dominant strategy, or a break that is Major or above on the bug bar. The release gate already reruns the red team. This adds the save-and-quit and stacking attacks, which the red team does not run.

## Rerun

From `sketches/core-loop`, with `G=$GODOT_BIN`, run one seed per process. bot_run forks multi-seed runs into children that run `bot_run.gd` itself, without this wrapper.

```bash
$G --headless --fixed-fps 90 --path . --script res://tools/sysaudit/break_run.gd -- \
  --out=<abs dir> --policy=skipper --seeds=<n> --table=park --until=2 --qa-log=1 --bot-no-visuals=1 \
  --break=spam|quit|stack [--quit-in=gates:3] [--spam-until=200] [--plant=damage=25]
```

`--out` must be an absolute path. Each run takes 3 to 10 minutes on the cloud box. The raw logs (`break-*.ndjson`, `qa-*.ndjson`, `bots.ndjson` and the console logs) are on branch `scratch/systems-audit-pass-f`. `runs.json` here has one line per run, named by attack and seed: `spam-`, `quit-`, `stack-`, `calm-` (spam stopped by `--spam-until`), `plain-` (no attack), `death-` (the planted death), `rep-` (a replay of the same command); `-v1` marks a quit run made before the resume check could see a lost clear; the three quits after a clear were rerun with the check, under the same name without `-v1`. The `tool` field says which version made each run. Runs made before review lacked the hold releases and the lost-clear check; their spam and stack rows stand, and the 6-of-6 count reads each quit's numbers in `runs.json`. One stacked run went on into world 2 (`--until=3`).
