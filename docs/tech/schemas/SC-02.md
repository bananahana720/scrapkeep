## Contract

### What this contract fixes

It fixes three schema types and six embedded records; the row map from HF-06a's three in-scope rows to those types; seven shared identity and version rules; a field table for every type and embedded record; twelve foreign reference rows; twenty-one admission rules, each bound to one HF-05 gate, one pair of failure edges and one diagnostic; the save treatment of every type against HF-06b and the HF-07a field list; six paper roundtrip expectations and four executable qualification obligations; one illustrative record per type with its paper encode and decode; and thirty-six tunable parameter rows, each carrying a source line or a question ID.

It is not a Resource and not a catalogue. No definition named here exists, no field has a production value, no candidate has been validated and no codec has run.

A "type" in the rules below is one of the three schema types. An embedded record has no domain ID, lives inside its parent's `.tres` and is addressed as the parent's ID plus a field path (HF-06a line 42; HF-05 line 111). Its fields, rules and illustrative values are specified under its parent.

Row allocation follows the rationale text. A type carries every in-scope row whose rationale contains a phrase in its basis cell, in both the HF-06a Markdown matrix and the CSV, and carries no other row; an embedded record's rows are a subset of its parent's. No row is re-treated (HF-06a lines 22, 46).

Each in-scope row adds exactly one type, and each type is added by exactly one row. A row may also restate a type another row added. "Restates" is not a second mapping: it records that the row's rationale names a type already added by another row, which is why that row appears in the type's row list, and it adds no type, field or identity.

N-020's rationale is "the committed attack definition (F-02)", which it restates, and it adds "SC-02 chaos-outcome definitions through TH-13"; HF-06b row N-020 calls its attack half "the same definition as F-02". An ultimate is the `ultimate` slot role of that one type rather than a second type, because TH-04 applies the same availability and cooldown rules to every slot action (TH-04 line 48) and adds charge only to the ultimate (TH-04 lines 42, 68).

`Presence` is one of `required`, `required if <field path>=<value>` (present exactly when the condition holds, forbidden otherwise) or `required, may be empty`. A required key is present even when its value is empty or null; an absent required key fails SC02-S01 and is never defaulted (TADR-003 line 31). `Value at this base` is either a closed vocabulary fixed by the cited source or `unset`, meaning each authored definition supplies a value only once the named parameter row's question is answered.

Engine realisation, from the Context7 retrievals and binding only as constraints. Each schema type and each embedded record is its own script file declaring `class_name` and extending `Resource`, because an inner-class Resource does not serialize its properties (q1). Every constructor parameter carries a default so the Inspector can create the definition (q1). `array of` fields are exported typed arrays and `enum{...}` fields are exported named enums (q4). An engine UID, reached as `uid://`, keeps resource references intact across renames and moves (q2) and is still not a domain ID (HF-05 line 18; TADR-003 line 25). A loaded definition is one shared cached instance (q3), which is why SC02-ID-06 below is an enforced rule and not a property of the file.

### Illustrative encode and decode

This is a documentary codec driven by the field tables above, not a `.tres` writer and not the JSON save codec. **Encode** walks the type's field tables in order, parent fields then each embedded record, and writes one typed entry per declared field the record holds: an `enum{...}` field as its vocabulary word, an `id-string` array as an ordered list of IDs, and every other field as its symbol, `null` or placeholder identifier. A key no table declares is not written. **Decode** reads each entry back by the declared type of its field and rejects an entry whose type does not conform, such as an enum stored as an ordinal. The paper check applies both to every record above and requires: every field the tables make present for that record appears and no forbidden conditional key appears; decode returns exactly the record's field set with equal values, so a field dropped from a table or a lossy entry fails; every reference field in the type's references table is equal after decode; and every decoded reference resolves to the illustrative record of its target type, whose family token equals the references table's expected family, or to a declared foreign placeholder: the device placeholder `illustrative.device.alpha` for row F-06, and the anchor key placeholder `illustrative.anchor.alpha` for row F-01, which a referring character definition would declare. Three references cross records: `illustrative.attack.alpha` names `illustrative.chaos_outcome.alpha`, and `illustrative.ability.alpha` names `illustrative.attack.alpha` and the device placeholder.
