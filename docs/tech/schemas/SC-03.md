## Contract

### What this contract fixes

Three definition types cover every HF-06a row this card produces. `ItemDefinition` is one authored found thing that can be acquired and equipped, whether it is plain equipment, a shared modifier or a transformation. `AttunementDeclaration` is the compatibility declaration embedded in an item. `RecipeDefinition` is one fixed secret recipe over selected endpoints. Each type is immutable admitted content resolved by gameplay content revision and domain ID (HF-05 lines 27, 35 to 37), carries no per-run field and declares no derived effect (TH-08 line 308). Everything a product answer owns is a parameter row with a question ID, and every illustrative record is labelled and uses placeholder identifiers.

This contract owns fields, not behavior. TH-08 owns the rebuild these fields feed, TH-09 owns loot routing, recipe evaluation and discovery writes, HF-05 owns admission, HF-07a and HF-07b own the durable fields and commits, HF-09 owns migration and TH-22 owns every executed round trip.

### Types and matrix rows

`ItemDefinition` carries rows N-015, a themed find, and N-025, equipment, shared modifier or transformation. N-015 and N-025 share this item type because HF-07a CSV rows 28 and 30 and HF-06b line 224 place them in the same item-instance projection; TH-20 records this pairing. `RecipeDefinition` carries F-08 and N-026, a family row and a noun row describing one type from two directions (HF-06a line 22).

| --- | --- | --- | --- | --- | --- |

An element shape is the typed element of an array or record field inside one type, such as an effect entry or a recipe endpoint. It has no domain ID, no admission of its own and no matrix row; it is addressed as the parent's domain ID plus field path, which is HF-05 line 111's `referrer` form, and it is listed in its parent's field table. Each element shape and the embedded record need their own named schema script, because a custom property on an inner class cannot be serialized (Context7 retrieval 1).
