## Contract

### Time and control boundaries

Encounter is the only gameplay-time owner. One active Encounter coordinator may complete one tick per eligible invocation of its `_physics_process(delta)` callback. There is no application accumulator, nested catch-up loop, actor clock or manually callable advance path. The engine can deliver multiple fixed callbacks between displayed frames; each remains a separate admitted invocation. Session owns lifecycle decisions and run/profile continuity, not an additional encounter clock.

Let `h` denote the approved fixed gameplay interval, which is currently unset. Advancing a tick means incrementing Encounter's tick position once and advancing all authoritative cooldowns, movement integration, windup/recovery durations, encounter timers and other time-dependent rules through that interval. Wall time, rendering delta, audio position and an animation's progress never substitute for `h`. Every authoritative time-dependent subsystem must be reached by Encounter's phase sequence. A new time-based rule cannot register its own callback.

Control changes do not advance gameplay time. Session may coordinate input clearing, pause, readiness, scene retirement and durable transition acknowledgment. Encounter may cancel uncommitted preparation or reject/drop invalid input requests through its existing `cancel_prepared`, `submit_action` and `retire` boundary. This non-advancing control drain changes only owned control/prepared/inbox state; it cannot decrement a cooldown, move an actor, consume randomness, apply damage or release a cast. Distinguish this permission from the sole tick callback below.

All operations are serialized with the owned tick. A request raised synchronously during a tick is latched as control work, not recursively executed against half-updated records. The current admitted tick finishes its committed batch, then Session performs the control drain before another tick can begin. Requests cannot retrospectively erase already committed attacks. No later input event may turn a focus-loss clear into a release edge.

The existing HF-03a dependency directions remain binding: Session calls its six services; Encounter calls CollisionQueries and reads InputAdapter; Persistence uses ContentAdmission's resolver. Return values use those same edges. Presentation only supplies UI request values for Session to read. No new module, reverse Session callback or global gameplay bus follows from this section. Phase/control fields refine the existing SessionControl, TickState, EncounterInbox, QueryBatchState and InputContextState records.

### Callback that may advance gameplay time

| Callback ID | Engine callback                                                    | Sole owner | Admission and effect                                                                                                                                                                                                                                                     |
| ----------- | ------------------------------------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| C-TICK      | `_physics_process(delta)` on the active Encounter coordinator only | Encounter  | Complete phases P0–P6 once when initialized, current, unpaused and outside a held transition. Reject reentry and retired/unready invocations. Only successful P6 increments the tick. Helpers run synchronously inside this invocation and cannot schedule another step. |

Session establishes one active encounter identity before enabling it, and closes the outgoing coordinator before admitting a replacement. Encounter enforces its own initialization, retirement and in-phase guards. Session enforces session-level holds through the solo pause state; Encounter also retains its own held-error state. Encounter never reads SessionControl through a reverse import. The implementation must prevent a second coordinator from becoming eligible; an autoload or node name alone is insufficient. A physics-frame indication alone also grants no authority to an unrelated caller.

The production Encounter is pausable. Session's bounded control drain, InputAdapter's clearing and required menu/UI handling must remain callable during a pause. Presentation may update menus and cosmetic display state while gameplay remains frozen. Godot documents that signals can still invoke connected methods on paused nodes; therefore every queued/connected delivery still needs identity and state checks. Do not reactivate gameplay physics servers or run another always-processing combat node to bypass pause. Process-mode implementation must be qualified on the approved native fixture. See [pause behavior](https://docs.godotengine.org/en/4.7/tutorials/scripting/pausing_games.html).

### Fixed-tick phases

P0 can exit without advancing time. P1–P6 form one serialized owned tick; no phase waits for a later callback or exposes partial gameplay results. Staging here means private working state inside HF-03a's owned records, not another module or a save transaction.

| Phase                            | Owner and interface                                                           | Required ordering and result                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0: eligibility                  | Encounter, C-TICK guard                                                       | Check current initialized encounter, unpaused state, no retirement/held error and no reentry. Finish any required non-advancing cancel drain before sampling actions. A rejected invocation does not consume an input frame or increment the tick.                                                                                                                               |
| P1: command boundary             | Encounter `submit_action` / InputAdapter `read_frame`                         | Capture one immutable command batch and input frame for this tick. Validate encounter/input generation, command identity and current permissions. Reject stale/duplicate/invalid requests; later arrivals wait for a later boundary. Consume each physical edge at most once.                                                                                                    |
| P2: rules and intent             | Encounter composed controllers                                                | Evaluate current actions and due time-dependent rules using the same `h` and admitted definitions. Derive movement/action intents and staged timer changes in documented stable order. No actor callback supplies another delta. Product admission policies remain with their question/producer cards.                                                                           |
| P3: movement and synchronization | Encounter requests CollisionQueries `resolve_movement` / `interpret_contacts` | Start from the last committed authoritative poses and one identified collision-world revision. Resolve movers in stable entity-ID order; later movers see prior resolved physical updates in that order. CollisionQueries completes and identifies the post-movement query world before any attack query. Encounter stages the returned gameplay poses and contact consequences. |
| P4: attack commitments           | Encounter requests CollisionQueries `query_attack`                            | In the frozen command/entity order, revalidate provisional actions against the post-movement world, then resolve a newly committed attack's geometry, targets and random outcome once. Existing windups use their committed geometry contract. Capture the results in AttackLedger; Presentation cannot rerun these queries.                                                     |
| P5: outcome application          | Encounter                                                                     | Apply the staged immediate outcomes once in the declared order, including contact consequences and attacks. Revalidate target eligibility against already applied outcomes without rerolling or changing committed geometry. Determine encounter/reward result values; no direct RunState/ProfileState mutation occurs here.                                                     |
| P6: commit and publish           | Encounter publishes for `read_committed_results`                              | Commit the complete tick, increment tick position once and publish detached snapshots plus identified committed results. Release the phase guard. Session may subsequently read results and route explicit run/profile transitions; Presentation displays the published data. Neither reader adds another tick.                                                                  |

The collision adapter must prove that P3's body updates and P4's queries observe the declared world and coordinate frame. Node update priority or a visual transform does not establish this. CollisionQueries owns body/query bindings and contact interpretation; Encounter owns the committed gameplay pose. There is no visual-transform writeback. Collision callbacks may collect observations, but Encounter consumes only observations belonging to the qualified phase/world revision.

If the adapter cannot establish synchronization, or a required phase fails, do not publish a successful partial tick. Hold the encounter with the last complete gameplay result and a diagnostic; refuse another step until the physical world is restored to that committed state or the encounter is safely replaced. Recovery/reconstruction must be verified before automatic retry is implemented. This document selects the ordering requirement, not an untested Godot flush API or a custom physics engine. Real-world contact ordering and synchronization remain unqualified.

### Command admission and result lifetime

Session authorizes lifecycle/build requests. Encounter owns EncounterInbox and decides action validity at P1/P4. InputAdapter supplies physical state and immutable edges; an input callback only submits a request. Commands identify their encounter, input-context generation and request identity. Same-boundary input edges follow recorded arrival order; autonomous actor work uses stable entity IDs. Each newly submitted command after the captured boundary waits for the next one. Duplicate request identities cannot repeat an action, and replaying an old input frame cannot create another edge. These are ordering requirements, not cross-platform determinism claims.

Held movement/aim samples may replace older unconsumed continuous samples. Discrete action edges must not silently disappear or accumulate into a post-pause burst. A focus/modal/input-context change invalidates the old generation and discards its uncommitted gameplay requests. Cancellation remains explicit even after that discard. Requests while paused, unready or retired are rejected as gameplay actions; menu requests still reach Session. Actual action legality, cooldowns and opportunity rules are revalidated by their owner rather than accepted because a button looked enabled.

Every published result carries its encounter identity and tick/result identity. Published snapshots are immutable detached values, including nested collections. Presentation holds previous/current snapshots from the same encounter, interpolates within that pair and never extrapolates gameplay outcomes. With no newer snapshot it holds the last authoritative pose; cosmetic/UI animation can continue. On a pause, snap/hold to the last committed state instead of visually advancing a threat timer. On replacement, clear the old interpolation pair before displaying the new initial snapshot.

Latest snapshots may supersede older display snapshots. Committed gameplay result batches are retained until Session has read and accepted their identified values; a slow renderer is never the retention authority. Session places any pending durable transition in its own PendingTransition before the outgoing encounter is discarded. Presentation's cue-consumption state prevents duplicate cosmetic playback but does not acknowledge gameplay settlement. A repeated read cannot settle rewards twice. Resource references remain pinned until their consumers release them through existing Session/ContentAdmission routing. Numeric queue/history limits are unset under Q-E03; exhaustion must hold with a visible diagnostic, not discard unresolved gameplay results.

### Four separate operations

| Operation                       | Owner and existing interface                              | Order and exact effect                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| O1: release held physical input | InputAdapter `clear_physical_input`, requested by Session | Clear held state, previous-edge state and pending physical edges; advance the input-context generation. Consume the pause/resume/capture UI action as UI input. Re-arm each gameplay control only after observing it neutral in the new context, so a still-held key/button cannot reappear as a fresh press. This produces no gameplay release edge and cannot cancel Encounter preparation by itself.                  |
| O2: cancel prepared actions     | Encounter `cancel_prepared`, requested by Session         | At a serialized control boundary, discard old-generation queued gameplay requests and clear uncommitted prepared actions. Return only after the cancellation is applied; if a tick is in flight, latch and finish the drain before another tick or resume. No cooldown/time increment, damage, new random draw or cast occurs. Existing committed windups/outcomes retain their contract.                                |
| O3: solo pause                  | Session `request_pause`                                   | After O1 and O2 for focus/modal/user-menu entry, hold the prior lifecycle state and set the engine solo pause state. Pause itself only stops future C-TICK admission and gameplay physics. It does not implicitly perform O1 or O2; direct internal pause must not be presented as the complete safe-menu sequence.                                                                                                      |
| O4: resume                      | Session `resume`                                          | Require a valid active encounter, no held critical/save error, applied O2 where required, valid input path/capture and resolved modal focus. Perform O1 again to consume the resume/capture action and require neutral re-arm; restore the prior eligible playing/intermission state and unpause last. Resume alone does not tick, release or synthesize a cast. The next eligible C-TICK is the first gameplay advance. |

Focus loss, dashboard entry and any modal transition out of gameplay use O1 → O2 → O3, then show the interactive UI. A notification received mid-tick is latched; Session completes that sequence at the first non-reentrant control boundary before another tick. Capture release/restoration is InputAdapter's input-context work, coordinated by Session. A rejected capture keeps pause and exposes retry; that retry action cannot also become a shot. A supported non-mouse input path can satisfy resume readiness, but hardware support is not established here. Regaining focus alone never resumes gameplay.

A pure internal pause remains separable, as S0-04 phase D demonstrates; it does not cancel a prepared action. Any route exposing pause to user focus/menu navigation must use the safe sequence. This avoids relying on a bare pause primitive as accidental-cast protection.

### Overload policy and rates

Use one complete `h` per eligible engine invocation. A slow displayed frame does not authorize additional application steps, a larger delta, skipped damage checks, accelerated cooldowns or rerolled outcomes. If the engine delivers fewer ticks than real time would suggest, gameplay falls behind wall time. The application does not reconstruct that wall-time debt. If several engine callbacks arrive before rendering, they run the normal phases individually; each new physical edge is consumed once, while continuous samples may remain held.

Presentation may reuse the last result and omit optional cosmetic updates, while preserving committed threat geometry and required feedback. Mandatory gameplay work stays intact. If a tick cannot complete safely, or command/result storage cannot retain required work, use the held-error path described above, clear/cancel input through Session and show a diagnostic. Do not automatically resume by dropping unresolved results or weakening collision checks. A numerical overload detector, queue capacity or engine catch-up cap must be specified and qualified before a dependent implementation uses one; this contract chooses no threshold.

Route the unset simulation rate `h`/Hz and engine catch-up settings to HF-02's `B-frame` (`proposed:Q-E03`) and `N-frame` (`unmeasured native requirements`). Queue/history capacities also require a workload-backed Q-E03 proposal, with storage implications under `B-memory`/`N-memory`; transition/control latency belongs to `B-load`/`N-load`. These are references into the admitted register, not edits or accepted values. Runtime and Verification supply target/workload/method evidence; Andrew rules on budgets. The S0-04 engine-default 60 Hz, ten-frame phase waits and 600-frame test ceiling supply no production rate, capacity or overload threshold.

### Encounter replacement and teardown

Session owns the transition and keeps RunState, ProfileState and PendingTransition alive. The outgoing Encounter and its CollisionQueries world are replaceable. Replacement is serialized at a complete tick/control boundary with gameplay held. It is not an `_exit_tree` reward callback.

1. Session marks the outgoing identity as closing and rejects new gameplay input for it. Use O1 and O2, then hold ticking with O3. Read and accept its completed result batches through `read_committed_results`; settle or retain the identified transition under Session. Critical durability requirements remain under HF-07; an unresolved critical write blocks playable replacement.
2. Session calls Encounter `retire`. Encounter permanently rejects action submission and C-TICK for that identity, invalidates queued work and preserves only the final values Session still needs. It calls CollisionQueries `detach_world` through the existing edge. No physics/contact result from that world may enter another encounter.
3. Session disconnects each scoped subscription it established. Each module removes subscriptions it owns and cancels its outstanding scene-bound timers/awaits where supported. The connection records live with that owner's existing lifecycle records. Every delayed callback also checks encounter generation and retirement; disconnect/free alone is not assumed to erase already queued calls. Late results are rejected, never rebound to the replacement instance.
4. Session calls Presentation `release_encounter_views`, clears old cue/interpolation state, and frees the outgoing composition at a safe lifecycle boundary. Teardown completion is required before any replacement may tick. Session and its persistent services are not children whose lifetime ends with that encounter.
5. Session resolves the admitted pinned content through ContentAdmission and supplies fresh value initialization/build data to a newly created Encounter with a new identity. Encounter initializes its CollisionQueries bindings. Scene-ready notifications are observations; Session waits for explicit initialization, world readiness and view readiness before declaring it eligible. A failure keeps gameplay held with a diagnostic and does not discard run/profile state.
6. Publish an initial same-encounter snapshot, bind scoped result readers/notifications and restore input context through O4 when the intended state is playable. No old held action, timer, deferred callback or snapshot crosses the generation boundary. The replacement's first C-TICK starts its own encounter tick sequence while run continuity remains with Session.

### S0-04 reconciliation

The named S0-04 trigger has fired and is reconciled now through source and retained evidence inspection. Phases A/B assert owned invocation counts, rejection of process/timer advancement and scalar snapshot isolation. Phase C asserts one synthetic prepare/release cast. Phase D asserts a frozen tick with an always-processing menu and preparation retained by bare pause. Phase E asserts cleared held input and frozen tick during pause, then empty preparation, no additional cast and resumed tick counts.

The actual [session source](../../../native/proofs/tadr-002/session_owner.gd) clears input, queues `cancel_prepared` and pauses. The [coordinator](../../../native/proofs/tadr-002/encounter_coordinator.gd) drains that queue on the first resumed tick before reading input. In [phase E](../../../native/proofs/tadr-002/proof_runner.gd), `pending()` appears in the printed message; the assertion does not test the pending queue. Therefore this section claims neither an asserted pending-cancel invariant nor cancellation completed while paused from that proof.

This contract requires applied non-advancing O2 before safe pause/resume completion. It refines the open timing choice in the proof and preserves TADR-002's owner and no-manufactured-cast rule. It has not been executed. Neutral re-arm, full command-generation invalidation, real OS focus/capture, scene teardown, positive committed-result delivery, nested snapshot isolation, complete production callback coverage, physical-world order and overload behavior remain unqualified. The direct `_state.tick` injection shows that the proof detects a foreign write; it does not show GDScript prevents it. No historical source was changed or rerun.
