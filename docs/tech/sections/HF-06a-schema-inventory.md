## Contract

### Row identity

A matrix row has a stable row ID that downstream cards cite as an "HF-06 matrix row". Family rows are `F-01` to `F-08` in the order TADR-003 line 25 enumerates them. Noun rows reuse the supplied noun IDs `N-001` to `N-059` unchanged. Row IDs are never reused or renumbered. Changing a row's treatment or producing card requires a card revision recorded in TRACKING, and the CSV changes in the same candidate. A family row and a noun row may describe the same definition type from two directions (for example F-03 and N-024); each row still carries exactly one treatment, and the noun row names the family row it instantiates in its rationale.

Row identity is documentary. It is not a domain ID, not a filename and not an engine resource identifier. The domain ID of any definition a row describes follows HF-05 line 18: opaque, nonempty, case-sensitive, issued with the definition, unique across the admitted catalogue (HF-05 line 22), and independent of path (S0-05 line 37). The production ID grammar belongs to the producing SC card.

### Treatments

`schema` means an authored definition type with its own domain ID, saved as a typed text `.tres` under `native/content/<unit>/definitions/` (HF-01 line 28; HF-03a line 23; HF-05 line 29), resolved through the catalogue by `resolve_id` (HF-03a line 34), and validated by ContentAdmission's four gates (HF-05 lines 45 to 52). A schema row for a Bible candidate (a region, a pilot) fixes the definition type that the candidate would be authored as. It does not admit that candidate: candidate names and reference concepts stay outside production content until a product decision selects them (TADR-003 line 35; Bible line 169, line 273).

`embedded-record` means an authored typed record that lives inside a parent `schema` definition and has no catalogue domain ID of its own. It is addressed as the parent's domain ID plus a field path, which is the `referrer` form of HF-05 line 111, and it is validated inside the parent's structural and semantic gates. Its producing card is the card that owns the parent definition. Embedded records inherit the parent's immutability (TADR-003 line 29; HF-05 line 37) and may contain no per-run state.

`excluded` means no authored gameplay definition exists for the row. The rationale names which of three cases applies: the row is mutable runtime or persistence state owned by a record in HF-03a lines 45 to 51; the row is guidance, direction or process consumed by a card rather than data; or the row's meaning is already fixed by another row and a second definition would create a second editable truth (TADR-003 line 35). An excluded row still constrains its producing card.

The producing card's obligation follows the treatment. For a `schema` row it authors the definition type: fields, types, identity and version rules, references, validation diagnostics and one labeled illustrative record (the DoD shared by SC-01 to SC-08). For an `embedded-record` row it authors the record inside its parent type. For an `excluded` row it consumes the row as a constraint and confirms at its own review that no authored definition is needed; if that confirmation fails, the row returns here for re-verification rather than being re-treated inside the consuming card.

All validation named in this matrix is ContentAdmission's (HF-03a line 34; HF-05 line 31). An editor tool under `native/editor_tools/**` may invoke those validators on canonical definitions; it is not a second validator and holds no independent truth (HF-01 line 36).

### Question-shaped rows

Each row that Q-P14, Q-P15 or Q-E09 shapes carries the question ID and a treatment that holds under every candidate answer. The invariance argument for each question:

- [Q-P14](../../../BACKLOG.md#q-p14) leaves open which item and endpoint combinations are eligible, what fixed bonuses or harmful tradeoffs apply, and what the player learns before and after discovery. Rows F-08, N-015, N-016, N-017, N-025 and N-026 carry it. Under every answer, an item, modifier or recipe is still an authored definition with a domain ID, eligibility is still a set of references validated for existence and expected family (HF-05 line 51), and a bonus or tradeoff is still a reviewed behavior identifier (TADR-003 line 23). Disclosure becomes either a field on the recipe or discovery definition or a policy on SC-08's discovery definitions; both fit the named types. No row fixes a recipe, an eligible set or a disclosure rule.
- [Q-P15](../../../BACKLOG.md#q-p15) leaves open companion chassis, components, autonomous support and commands, plus device capacity, lifetime, recall, resource and cross-level persistence rules. Rows F-06, F-07, N-016 and N-027 carry it. Under every answer, a device is an authored definition with an action reference, and at least the companion chassis is an authored definition, so both families remain `schema` even if interchangeable components collapse to one part or commands collapse to autonomous behavior only. Capacity, lifetime, recall and resource rules are typed symbolic fields whose presence the schema requires and whose values the answer supplies. Cross-level persistence is a save-column decision for HF-06b, not a treatment here.
- [Q-E09](../../../BACKLOG.md#q-e09) leaves open which discovery facts become durable immediately and which wait for a completed-level or terminal commit. Rows N-017, N-026 and N-028 carry it. Under every answer, the discovery, recipe and permanent-unlock definitions are immutable and resolved by ID; the profile knowledge that references them is ProfileState (HF-03a line 45) projected by HF-06b and committed under the HF-07b protocol. Write timing changes when a projection commits, not what is defined.

Two other open questions are named in a matrix rationale cell without being registered on this card: [Q-P13](../../../BACKLOG.md#q-p13) in row N-010 and [Q-P16](../../../BACKLOG.md#q-p16) in row N-028. They are cited so the producing card keeps those values symbolic; they do not change a treatment. No other question ID appears in a rationale cell. Q-P10 is named only in Unresolved questions, which records where it and Q-P13 keep milestone allocation and chaos limits symbolic; that is a pointer to the open decision, not a matrix gate.
