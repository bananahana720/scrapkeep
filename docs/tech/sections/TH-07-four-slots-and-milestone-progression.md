### Owned data

Definition-of-done item 5's second requirement. This contract reads and writes exactly the records the state table assigns, through the interfaces above, and nothing else.

1. **Session writes `SessionControl`, `RunState`, `ProfileState`, `EffectiveBuild` and `PendingTransition`.** The progression controller is a composed controller inside Session's boundary, not another mutation owner (HF-03a line 21). `RunState` holds the build-slot selections; `EffectiveBuild` holds the rebuilt derived set; `ProfileState` holds the discovery knowledge an endpoint recipe is recognised from. Session settles each accepted milestone once, rebuilds from all current selections and installs the result as values (HF-03a lines 45, 57). It never writes a durable record.
2. **Encounter writes `EncounterState`, `TickState`, `AttackLedger`, `EncounterRandomState` and `EncounterInbox`.** It receives the installed capability set, the definitions and a seed as values, determines milestone result values at P5, publishes them at P6 and holds no writable `RunState` alias (HF-03a line 46). It never sets `unlocked`, never appends a node key, never resolves a definition ID and never installs a rebuild.
3. **ContentAdmission writes `CatalogueAdmissionState` and `CatalogueRegistry`.** It validates the tree shape at admission, and the run's pin selects a revision without modifying the catalogue. A selection changes a run fact, never an admitted tree definition (HF-03a line 48; HF-05 lines 35 to 37, 50).
4. **Persistence writes `SaveTransactionState`, `DurableAggregate`, `PreferencesRecord` and `RecoveryState`, and it alone stages or replaces them** (HF-03a line 49). Session supplies the accepted inputs on D04; Persistence builds, validates, commits and acknowledges the candidate (HF-07b lines 37 to 40). HF-10 required fix RF-6 at line 64 records the one admitted scenario step that reads otherwise; this section states the ownership HF-03a fixes. No progression fact travels through `PreferencesRecord`.
5. **CollisionQueries writes `CollisionWorldState` and `QueryBatchState`.** It resolves the installed extent and returns movement and contact results. It commits no pose, unlocks nothing and evaluates no selection (HF-03a lines 33, 47).
6. **InputAdapter writes `PhysicalInputState` and `InputContextState`.** Clearing physical input cannot mutate a selection, a prepared action, a pause state, a save or the run, and an input callback only records a request (HF-03a line 50; HF-04a line 46).
7. **Presentation writes `PresentationState` and `FeedbackState` from published values.** The tree display, the branch comparison, the locked-slot indicator and every cue are display state built from detached copies. Presentation decides no availability, marks nothing unlocked and stores no dashboard state (HF-03a lines 37, 51; HF-07a line 128; TH-04 line 56).

The one derived record is `EffectiveBuild` and it has one writer. A second copy of a derived node effect anywhere else is a second authority and a defect, whatever it is called (HF-03a line 58).

### Seams stated and not decided

**Seam 1: the rebuild, to TH-08.** A tree selection is one of the three inputs to the rebuild TH-08 owns, and this section adds no second rebuild, no fourth input, no pass and no derived record. What a node's declared effect is eligible for, how two rows declaring the same effect combine and what a fixed secret bonus grants are TH-08's interfaces with Q-P14 and Q-P19 open. This section fixes only that a tree selection enters those interfaces as a selection and leaves them by the same whole replacement.

**Seam 2: what an unlocked slot means for an action, to TH-04.** Availability, cooldown, charge, effect lifetime, the refusal of a locked slot and the revalidation at P1 and P4 are TH-04's and are restated nowhere here. This section fixes the access and selection facts those rules read and nothing about what the action does.

**Seam 3: the growth path and the install boundary, to TH-05.** That a milestone reaches the run as an accepted result, that recovered material is consumed as collected, and that the authorized boundary for a growth-bearing rebuild is the intermission are TH-05's, adopted under Q-P10's recorded partial answer. **Seam 4: the node, tree and slot schema, to SC-01 through HF-06a rows F-03 and N-024.** Slot-tree definitions with their embedded node and edge records, addressed as tree ID plus node key, are `schema` work whose producing card is SC-01 and whose open content is Q-P11. This section names no field of those definitions. What it requires of them is the shape PT-01 to PT-06 fixes, a domain ID per tree, a key per node, and no per-run field on the admitted path.

**Seam 5: the respec opportunity as content, to SC-04 and Q-P18.** HF-06a row N-024 at line 97 records that a respec opportunity is an F-04 objective definition (SC-04) under Q-P18, not an SC-05 event definition, because TH-06 UN-05 at line 119 places event and secret-room types among a level's objective definitions. **Seam 6: devices and one main companion, to TH-10.** TH-10 was written concurrently and admitted at TRACKING EV-0311; it is cited nowhere here. Rechecked at the Handoff-5 closure integrated read (TRACKING EV-0325) against the admitted bytes with no change needed.
