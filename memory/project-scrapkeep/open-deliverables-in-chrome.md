When I produce something for Andrew to see or hear, open it in his Chrome and give the path in the reply. On 2026-10-02 he said he could not see the sound page or the keyframe images I had sent with SendUserFile, and then: "on a go forward basis, just open it on my browser, my Chrome browser. I usually always have that open, so I can always find it there."

**Why:** the file cards did not appear where he was looking (desktop app, Code tab), so material I believed delivered was never seen; a sound-preference question sat unanswered for hours because of it.

**How to apply:** build one self-contained HTML page per review (images and audio embedded, so it survives being moved) and run `google-chrome-stable "file:///abs/path.html"`, which adds a tab to his running instance (`/opt/google/chrome/chrome`; default browser is google-chrome.desktop). Say in the reply that a tab was opened and what it is called. This is the one standing exception to [[gui-work-off-andrews-screen]] in home memory: my own working windows still go headless or to workspace 10, and only finished material for him goes to Chrome. My reading, not his words: it applies to every project on this machine, not just Scrapkeep. Do not open a tab per file; batch into one page, since he counts pop-ups as clutter.
