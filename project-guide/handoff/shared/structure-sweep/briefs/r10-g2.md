## The unit

This unit turns one rule that writers and reviewers keep by hand into a check that fails: a dated record of past work is not rewritten. All of it is Node code under `scripts/`, one small list file, one line in the CI workflow and one in the pre-push hook.

**Part 1: the check, `scripts/dated-records.mjs` with `scripts/dated-records.test.mjs`.** `node scripts/dated-records.mjs --base <ref>` compares each listed page at `git merge-base <ref> HEAD` with the same page at `HEAD`, and exits 1 with one finding per page that broke its rule. Two kinds of page:
- **frozen**: no line may change, be added or be removed, and the page may not be deleted or renamed.
- **log**: every line that is in the base copy is still in the head copy, unchanged and in the same order; new lines may be added anywhere (a notes log gets new entries, and `sketches/core-loop/DESIGN-NOTES.md` says each writer adds inside its own section). The page may not be deleted or renamed.
Each finding names the page, quotes the first base line that changed or went missing, and says what to do instead, in the message itself: a dated record keeps the names and paths it was written with; put the new fact in the page that describes the project today, or add a new dated entry; if the page should no longer be protected, remove it from the list in the same change and say why in the pull request. A page that is on the list but not in the base commit is new and passes. A page that is in the base commit and on the list at the base but is dropped from the list at the head passes too (the list edit is what a reviewer sees); print one line that names each page dropped from the list so it cannot go unseen.

**The check must never pass without having checked.** Two reviews in this sweep each found a new check that reported a pass when it could not read its input, so treat each of these as a failure with a message that says what could not be read and what to do: `--base` missing or a ref git cannot resolve; `git merge-base` failing; a page that is in the base commit's tree (ask with `git ls-tree`, which needs no file content) but whose content git cannot read (CI uses a blobless clone, so a read can need a fetch, and a fetch can fail); a list file that is missing, is not valid JSON, or names a path or a pattern that matches no tracked file. Use `git()` from `scripts/lib/git.mjs` for calls that must succeed, and do not turn a failed call into an empty answer. Exit codes: 0 every listed page kept its rule; 1 at least one finding; 2 the check could not run. Compare the lines yourself from the two copies (a small longest-common-subsequence or a walk with two indexes is enough); do not parse `git diff` output.

**Part 2: the list, `scripts/ci/dated-records.json`.** Two arrays, `frozen` and `log`, of repo-relative paths; allow a `*` pattern only if it removes many lines and say how it is matched. Build the first list from evidence, and keep it short and certain: a page goes on it only when its own text says it is a snapshot, a ledger, a receipt or a record kept as written, or when it is one of these named ones. Start with: `docs/art/reference/GROUNDING.md` (frozen); the twelve survey files of this sweep under `project-guide/handoff/shared/structure-sweep/` (every `.md` there, frozen; list them, and say whether a pattern is worth it); `sketches/core-loop/DESIGN-NOTES.md` (log). Then search for others (`git grep -l -i -E 'kept verbatim|historical snapshot|append-only|appends only|preserved as written' -- '*.md'`, the wave memos and receipts under `project-guide/handoff/`, `sketches/core-loop/perf-lab/ledger.md`) and read the top of each hit. Add one only when its own words make it frozen or a log; put every page you looked at and left off, with the reason, in your report. Do not add `BACKLOG.md`, `TRACKING.md`, `DECISIONS.md` or `STATE.md`: live pages with history in them, edited every day. Before you put a page on the list as a log, check its own history: `git log --format=%h -15 -- <page>` and look at whether past commits changed existing lines. If they did, often and for good reason (a table that is kept current, not a list of entries), it is not a log; leave it off and say so.
