## The unit

This unit closes five small holes in the Node tests and checks: places where a check passes without checking, or fails for a reason that is not a defect. All of it is Node code under `scripts/`.

**Part 1 (LEAD-48), six tests assert on wall-clock time.** Three in `scripts/alpha-rc.test.mjs` and one each in `scripts/gate/display-run.test.mjs`, `scripts/gate/look-receipts.test.mjs` and `scripts/lib/proc.test.mjs` assert that something finished within a number of milliseconds (find them with `git grep -n -E 'Date\.now|performance\.now|elapsed|< *[0-9]{3,}' -- <file>` and read each). A test like that fails on a slow CI runner with no defect; one did, and an earlier unit fixed it by counting the work instead (`git log --format='%h %s' -3 -- scripts/ledger-audit.test.mjs` and read that diff). For each of the six, find what the assertion was written to prove (no quadratic loop, a timeout that fires, a wait that is not skipped) and prove that directly: count the calls, the reads or the spawned processes, or inject the clock or the delay so the test controls time. Keep an upper bound on time only where the subject is a timeout itself, and then make the test control the clock. If one of the six cannot be changed without changing the script it tests in a way that is not small, leave it and say why. No assertion may become weaker: each rewritten test must still fail if the defect it guards against comes back, and you show that for each by breaking the subject on a scratch copy.

**Part 2 (LEAD-21), the test runner lists files from the disk.** `scripts/ci/node-tests.mjs` walks the disk for `*.test.mjs`, so an untracked test file under `scripts/` runs on one machine and not on another, and a tracked one that is missing from the disk is not noticed. Make it list tracked files (`git ls-files`) and fail, not pass, when that call fails or returns nothing; a new test file a writer has not yet added to git should still run locally, so include untracked files that are not ignored (`git ls-files --others --exclude-standard`) and print one line naming each. Read how CI calls the runner (a sparse checkout, shards) and keep the shard split stable. Then two smaller items from the same row: `npm test -- --test-name-pattern=<pattern>` exits 2 today; either pass the option through to `node --test` or refuse it with a message that names the working form, whichever is less code. And 21 test files added to the list by an earlier unit have no entry in `DURATION_HINTS_MS`, so the second CI shard may run long: read how the hints are used, measure the files that lack one with one run, and add hints only if the split is uneven by more than a few seconds; say what you measured.

**Part 3 (LEAD-23), two checks that report nothing where they should report a failure.** (a) `checkPreset` in `scripts/export-include-check.mjs` returns an empty list of problems when the `sketch` folder is missing, which reads as a pass. A missing folder must be a failure with a message that names the folder. (b) `scripts/crash-harvest.mjs` reports a broken symbolic link as `(missing)`. Read what a caller does with that: if a broken link is a real state it should report as such (say what the link pointed to), and it must not be counted as a harvested file. Add a test for each.

**Part 4 (LEAD-03), a moved script can break a page's link unnoticed.** CI and the pre-push hook run `npm run check:docs` only when a page, a skill or agent file or a docs script changes (the patterns in `scripts/ci/affected.mjs`; the hook reads them through `isDocsPath`). A unit that deletes or renames a script that a page links to breaks the link, and no check runs. `npm run check:docs` takes under a second. Weigh at least: always running it in the hook and in the CI job that owns it; or running it whenever a change deletes or renames any tracked file. Take the one with the least code that closes the hole in both places with the same rule, and prove it with a test: a change that deletes a `.mjs` file a page links to must select the docs check. `scripts/hooks/pre-push.mjs` and `.github/workflows/ci.yml` are being changed by another unit (see below): if your option needs a line in either, keep it to the fewest lines, away from the `dated-records` step, and say exactly which lines in your report.
