## The unit

Many Godot tests enforce a rule by reading the game's source: "only this file may declare that constant", "no file outside this folder calls that function". Thirteen times in this sweep a reviewer found such a guard that passes when it reads nothing: the folder did not open, the file list was empty, the read came back empty, or the pattern did not compile. The shared reader `SourceScan` fails the test in each of those cases, and seven tests use it. On the base 317 test files call `FileAccess.get_file_as_string`, 107 of them on a literal `res://src` path, and 127 list a folder with `DirAccess`. This unit makes the shared reader the only way a test reads script source, in three parts.

**Part 1, what the reader offers.** Today it has `matching(t, roots, pattern)` and `captures(t, roots, pattern)`, both over folders. Add only what Part 3's callers need, and no more. Two needs are known: reading one named script (`text(t, path)`, failing the test on an error or an empty read), and the declaration prefix that allows `static` and a same-line annotation, which `tests/unit/experimental_dev_seams_case.gd` holds today as its own constant `VAR_START`. Give the prefix one home in the reader and make that test use it. Every new call gets a case in `source_scan_case.gd` that shows it fail on a bad read. Keep the reader small: it reads and matches, and each guard keeps its own rule and its own list.

**Part 2, a lint rule so a new guard cannot read by hand.** Add rule `L19` to `scripts/sketch-lint.mjs`, with a shrink-only list in `scripts/sketch-lint.baseline.json` as the other rules have (`BASELINE_RULES` in that file; read how `L14` to `L18` are built and tested, and build this one the same way). The rule: a script under `sketches/core-loop/tests/` other than `tests/support/source_scan.gd` reads a `.gd` script's text by hand. Weigh how to recognise that with few false alarms; at the least it must catch `FileAccess.get_file_as_string` or `FileAccess.open` given a literal path under `res://src`, `res://tools` or `res://tests` that ends in `.gd`, and a `DirAccess` listing of a literal folder under those three roots. A test that reads a data file, a scene, a picture or a receipt is not an offence. Say in the report what the rule matches, what it knowingly misses, and how many files it lists. The message of a finding names the fix: "read script source through tests/support/source_scan.gd". Add tests to `scripts/sketch-lint.test.mjs` in the style of the other rules, including one that the list cannot grow. The pull request 1332 named below also edits `scripts/sketch-lint.mjs` and its test (the `L14` and `L18` code): keep your change to new functions and one new entry in each table so the two merge cleanly.

**Part 3, move the guards.** Move onto the reader every flagged file whose whole purpose is a source rule: the flagged `tests/unit/*_case.gd` files and the flagged `tests/*_owners_test.gd` and `tests/*_guard_test.gd` files. On the base those are about twenty files, among them `unit/sound_boundaries_case.gd`, `unit/ui_owners_case.gd`, `unit/mesh_fx_owners_case.gd`, `unit/world_constants_case.gd`, `unit/bmb_seams_case.gd` (it has its own `_read_src`), `movement_owners_test.gd`, `boss_owners_test.gd`, `dev_boundaries_owners_test.gd`, `craft_mesh_helper_owners_test.gd`, `presentation_random_guard_test.gd` and `pin_hash_guard_test.gd`. Do the first one by hand, then script the repeated shape if one emerges and commit the script under `sketches/core-loop/tools/` only if a later unit can rerun it; otherwise keep it out of the tree. For each file: it must report exactly what it reported before. Prove that by running the test before and after, and where a guard builds a list of findings, by printing the list both ways once. A moved guard holds no `FileAccess`, `DirAccess` or `RegEx.new()` of its own for script source, and its entry leaves the `L19` list. A test that reads source as one small step of a behaviour test stays as it is, on the list: do not widen this unit to all 107 files. ## Mistakes earlier units made

Each of these sent a unit back from review at least once. Check your work against every one before you hand in.
1. **A check that passes when it read nothing.** A test or tool you add or change must fail when it cannot read or compare its input: a folder that does not open, an empty file list, an empty read, a pattern that does not compile, a command that exits non-zero or prints nothing. A Godot test that reads source to enforce a rule does every read through `sketches/core-loop/tests/support/source_scan.gd` (`SourceScan.matching` for the files that match, `SourceScan.captures` for what each match captured) and holds no `FileAccess`, `DirAccess` or `RegEx` of its own. Write each such check as "the files that match equal exactly this list", and say in your report how the check fails on the code before your change.
2. **A pattern narrower than the language.** A pattern for a declaration must allow `static` and an annotation on the same line: start it with `(?m)^\s*(?:static\s+|@[a-z0-9_]+(?:\([^)]*\))?\s+)*`.
3. **A forwarding copy left behind.** When you move a function or a constant, delete the old one and change its callers. Keep a one-line forwarder only for a caller outside the folders you may change, and name that caller.
4. **A test weakened in passing.** When a signature changes or gains an optional argument, read every test that calls it and confirm each still exercises what its label says.
5. **An edited record.** Never edit a dated record of past work, not even a path that moved: ledgers, receipts, wave memos, the survey files, entries in `sketches/core-loop/DESIGN-NOTES.md`, and dated specs such as `design-v3/SKILL-BAR.md`, `design-v3/FEEL-READABILITY.md`, `design-v3/pilots/*.md` and `research/comps/*.md`. Live pages you do keep current: `ARCHITECTURE.md`, `CONTRACTS.md`, `VISUAL-LANGUAGE.md` and every `SEAMS.md`.
6. **A stray file committed.** Stage files by name. Never `git add -A` or `git add .`: your checkout may hold an untracked `node_modules` link.
7. **A test filter that matched nothing or everything.** `npm run sketch:fast` refuses an argument it does not know. Each `--test` takes one pattern matched against the test file's name, and each is its own argument: `--test unit_suite_test --test boss_owners_test`.
8. **A grown list.** `scripts/sketch-lint.baseline.json` only shrinks. If it conflicts when you merge, keep the integration branch's blocks and remove only what `npm run sketch:lint` says no longer offends.
9. **Git started by hand in a script.** A Node script starts git through `scripts/lib/git.mjs`, which reads the repository of its `cwd` even inside a git hook.
