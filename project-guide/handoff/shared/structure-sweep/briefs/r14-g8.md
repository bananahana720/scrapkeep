It exits 0 for no mention, 1 for a mention, and 2 when it could not search, and a caller of the command must treat 2 as "nothing is known". Commit `737a8d06d09358876aa325aa307341379b3796c5` put the search inside a `try` block but left the loop that prints the result outside it, so a failure while printing ended the run with code 1.

The second failure: commit `df97cdbf308cb15b78c32f1cca0f3aad5be792f0` changed one path in `project-guide/handoff/shared/world1/difficulty-plan.md`. That page is a dated read of commit `75099fa70` (10 November 2026), and the project never edits a dated record of past work, not even for a moved path.

The unit has two commits. The first makes the command line of `scripts/no-caller.mjs` run through one exported function, `main(files, { cwd, log, error })`, which returns the exit code and returns 2 for a failure at any step; the script also exits 2 on an uncaught error. It adds a test that calls `main` with a print function that throws. It also applies two smaller notes of the same review: the test of a search that cannot run resolves its scratch folder before it sets `GIT_CEILING_DIRECTORIES`, and `tests/antigravity-hooks.test.js` gains two cases in which a scratch save path written with `%20` is allowed. The second commit is a plain `git revert` of `df97cdbf308cb15b78c32f1cca0f3aad5be792f0`.

Done looks like: no failure of `scripts/no-caller.mjs` can end with exit code 0 or 1; its output and exit codes for a search that works are unchanged; the difficulty plan's changed line reads as it did before `df97cdbf308cb15b78c32f1cca0f3aad5be792f0`; and nothing else changes.
