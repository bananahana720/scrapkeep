## The unit

The game builds its crafted meshes in code with `SurfaceTool`. The same few primitives are written several times: a box with bevelled edges, a bevelled cylinder, a bevelled ring, a closed torus, a faceted orb. This unit folds the copies that produce the same vertices into one owner and leaves the ones that do not, with the proof either way.

**The rule that decides everything: no mesh changes by one vertex.** Before your first edit, build a census: a test or a tool script that builds every mesh the builders below produce (through the public entry points their existing tests already call), and for each records the surface count and a hash of every surface's arrays (vertices, normals, colours, UVs, indices) in a stable order. Run it on the base and commit its output under `sketches/core-loop/tests/fixtures/` as the pin (look at `tests/fixtures/pins/` for how pins are kept, and reuse an existing mesh pin if one already covers a builder). After every merge of two builders the census must match the pin exactly. Float noise is not an excuse: the same operations in the same order give the same bytes, so a difference means the merge changed the mesh; undo that merge and report it as a copy that is not the same. The census must fail when it builds nothing or reads no pin.

**What to compare.** Find the builders yourself: `git grep -n -E 'func _?(add_|append_)?[a-z_]*(bevel|chamfer|torus|faceted_orb|append_box)[a-z_]*\(' -- sketches/core-loop/src sketches/core-loop/tools`. On the base that finds, among others: `_bevel_box`, `_bevel_cyl` and `_bevel_ring` in `src/presentation/craft/enemy_boss_craft.gd`; `add_bevel_box` in `src/presentation/craft/camp_craft_meshes.gd`; `bevel_box`, `bevel_cyl`, `_bevel_ring` and `_bevel_box_masked` in `src/presentation/craft_prop_meshes.gd`; `add_beveled_box`, `add_torus` and `add_faceted_orb` in `src/presentation/crafted_ball_gear.gd`; `_add_chamfered_box` in `src/presentation/pilot_gear_kit.gd`; `add_chamfered_plate` in `src/presentation/craft/hero_kitbash_sculptor.gd`; `_add_closed_torus` and `_add_faceted_orb` in `src/presentation/world23_chunk_craft.gd`; and `_append_box` in `src/presentation/craft/vista_megastructures.gd` and `src/combat/dispatcher.gd`. Put the bodies side by side, family by family, and write down for each pair what differs: the order vertices are emitted in, where colour is set, how UVs are projected, whether a degenerate triangle is skipped, the segment counts, the argument order. Two builders are the same only when one can be written as a call of the other with fixed arguments and the census agrees.

**The owner.** Unit V1 already made one home for the flat-projection UV helper and the triangle helper; read where it put them (`git show c3501565dad2cf949b10a32ecd57054c9f8cbf95:project-guide/handoff/shared/structure-sweep/units.tsv` and then the code) and put the shared primitives beside them, in that same module, so a reader finds every `SurfaceTool` primitive in one place. ## Mistakes earlier units made

Each of these sent a unit back from review at least once. Check your work against every one before you hand in.
1. **A check that passes when it read nothing.** A test or tool you add or change must fail when it cannot read or compare its input: a folder that does not open, an empty file list, an empty read, a pattern that does not compile, a command that exits non-zero or prints nothing. A Godot test that reads source to enforce a rule does every read through `sketches/core-loop/tests/support/source_scan.gd` (`SourceScan.matching` for the files that match, `SourceScan.captures` for what each match captured) and holds no `FileAccess`, `DirAccess` or `RegEx` of its own. Write each such check as "the files that match equal exactly this list", and say in your report how the check fails on the code before your change.
2. **A pattern narrower than the language.** A pattern for a declaration must allow `static` and an annotation on the same line: start it with `(?m)^\s*(?:static\s+|@[a-z0-9_]+(?:\([^)]*\))?\s+)*`.
3. **A forwarding copy left behind.** When you move a function or a constant, delete the old one and change its callers. Keep a one-line forwarder only for a caller outside the folders you may change, and name that caller.
4. **A test weakened in passing.** When a signature changes or gains an optional argument, read every test that calls it and confirm each still exercises what its label says.
5. **An edited record.** Never edit a dated record of past work, not even a path that moved: ledgers, receipts, wave memos, the survey files, entries in `sketches/core-loop/DESIGN-NOTES.md`, and dated specs such as `design-v3/SKILL-BAR.md`, `design-v3/FEEL-READABILITY.md`, `design-v3/pilots/*.md` and `research/comps/*.md`. 6. **A stray file committed.** Stage files by name. Never `git add -A` or `git add .`: your checkout may hold an untracked `node_modules` link.
7. **A test filter that matched nothing or everything.** `npm run sketch:fast` refuses an argument it does not know. Each `--test` takes one pattern matched against the test file's name, and each is its own argument: `--test unit_suite_test --test boss_owners_test`. A `--test` replaces the tests the call would have picked from your changed files; it never adds to them, so the call that qualifies your unit carries no `--test`.
8. **A grown list.** `scripts/sketch-lint.baseline.json` only shrinks. If it conflicts when you merge, keep the integration branch's blocks and remove only what `npm run sketch:lint` says no longer offends.
9. **Git started by hand in a script.** A Node script starts git through `scripts/lib/git.mjs`, which reads the repository of its `cwd` even inside a git hook.
