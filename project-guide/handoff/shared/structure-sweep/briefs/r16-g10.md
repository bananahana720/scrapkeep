## The unit

This unit has three parts. Each gives one helper a decided answer for a case where today the answer depends on luck. It changes Node files and one page: no file the game loads, and it runs no Godot.

**Part 1 (LEAD-84), the safety hook always decides.** `.agents/hooks/safety-gate.mjs` is the hook that looks at a shell command or a file write before an agent's tool runs it, and answers `allow`, `ask` or `deny` as one line of JSON. It loads two repository files with `import` lines at the top: `scripts/lib/cli.mjs` and `scripts/lib/git.mjs`. If either cannot load (a broken edit to one of them, a checkout that lacks it, a syntax error in something they import), node stops with exit code 1 before the hook has printed anything, and nothing in the hook's contract says that such an exit blocks the call. The same holds for an error thrown inside `evaluateHook`. The hook already has the right answer for the one failure it expects: when its input is not JSON it prints an `ask` decision with a reason. Make every failure end the same way. The chosen design, and why: keep one home for each helper (do not copy `isMain` or `gitOptional` into the hook: two copies of each would drift, and the guards in `scripts/lib/cli.test.mjs` and `scripts/lib/git.test.mjs` exist to stop exactly that), so the hook's top-level `import` lines name only Node's own modules, it loads the two repository helpers at run time inside a `try`, and one place turns any failure to load or to evaluate into a printed `ask` decision whose reason says the safety hook could not run and names the error in a few words. The process must still exit with code 0 and one line of JSON on standard output in that case. Keep `evaluateHook` importable and synchronous for its tests if it is today; if loading at run time forces a change to how tests import it, make the smallest change and say what it was. Read the guards in `scripts/lib/cli.test.mjs` and `scripts/lib/git.test.mjs`: if either recognises a file by its `import` line, make sure the hook is still seen by the guard after your change (a guard that stops seeing the file is a blocking mistake), and show it in the report. Prove the part with tests that fail on the base, in the hook's existing test file: (a) copy the hook into a scratch folder where the two helper files do not exist, run it with a valid input, and assert exit code 0 and an `ask` decision; (b) the same with a helper file that exists and throws when loaded; (c) an input that makes `evaluateHook` throw, if you can make one without changing the hook only for the test (if you cannot, say so and test the one place that catches instead). Clean up every scratch folder in a `finally` block.

**Part 2 (LEAD-89), one order for finding Godot.** `resolveGodotBinary` in `scripts/godot-home.mjs` owns the answer to "which Godot binary". It has two orders today. Called with no `which` option, as almost every Node script calls it, it never looks on `PATH`. Called by the command form `node scripts/godot-home.mjs --bin`, which the shell and Python helpers use, it looks for `godot` on `PATH` before the version-named places under `/opt/scrapkeep-toolchain` and the home folder. No caller passes an option to get a different order.
