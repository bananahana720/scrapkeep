This unit turns three rules that writers and reviewers have kept by hand into checks that fail, and clears a handful of small script leftovers. All of it is Node code under `scripts/`.

Run the test (`node --test scripts/budget-audit.test.mjs`), confirm that is the only failure, and make the assertion hold every pilot to the same rule (bones and clips present), with no special case. The file is listed in `EXCLUDED_TESTS` in `scripts/ci/node-tests.mjs` with the reason that it fails on the base. Decide what is true after your fix: the CI job `node-tests` in `.github/workflows/ci.yml` checks out only part of the tree (read its `sparse-checkout` list). **Part 2, the lint's lists of existing offences may only shrink.** `scripts/sketch-lint.baseline.json` holds, for each lint rule, the offences that existed when the rule was added. The standing rule is that a change never adds an entry (it fixes the offence instead), and today only a reviewer's eye keeps it. Add a check that compares the file with its copy at a base commit and fails when any rule's list holds more entries than at the base, or when a rule that had no list gains one with entries. Compare counts for each rule, not the entries themselves: a file that moves changes an entry's path without adding an offence. The failure names the rule, both counts, the entries that are new, and the fix (fix the offence; for rule L14, register a reset in `sketches/core-loop/tools/test_batch_driver.gd`). Write the comparison as one exported function beside the code that reads the baseline, and call it from a place that already knows the base commit, so that the same command runs on a writer's machine and in CI: read how `scripts/sketch-fast.mjs` takes `--base` and how `.github/workflows/ci.yml` and `scripts/hooks/pre-push.mjs` find theirs, and pick the fewest call sites that cover a local run, the pre-push hook and CI. A new rule's first list (see Part 3) must be possible: allow a rule key that does not exist at the base. Prove the check with tests on made-up lists: one added entry fails with the message above, a moved entry passes, a removed entry passes.

**Part 3, every script has its uid file.** The repository tracks a `NAME.gd.uid` file beside every `NAME.gd` under `sketches/core-loop/`. A script committed without it gets a new identity on every machine. No check covers this today (`git grep -n 'gd.uid' -- scripts/sketch-lint.mjs` shows only an allowed-names message). Add a rule to `npm run sketch:lint`, in the form its whole-tree rules already use, that fails for a tracked `.gd` with no tracked `.gd.uid` beside it and for a `.gd.uid` with no `.gd`, naming the file and the fix (run a Godot import and commit the `.uid` file; delete the orphan). If the tree has offenders today, do not create or delete uid files in this unit: list them under the new rule's key in the baseline file, the way the lint's other rules began, and name them in your report.
