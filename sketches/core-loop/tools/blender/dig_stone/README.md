# Dig stone scenery

Eight static GLBs follow the D1 stone file contract. The recipes author continuous
surfaces in Godot metres, convert to Blender Z-up and export back to glTF Y-up.
They use the existing `common.py` export and index canonicalization helpers without
editing them. They opt into polish (`tools/blender/POLISH.md`) with no bevel or
subdivision: smooth shading with hard creases and the AO and wear bake on the grayscale
wear colour. Every GLB has one mesh and one `stone` surface. No colliders, lights,
cameras, animations, placement code or registry entries are exported.

Run from the worktree root with Blender 5.2.2 LTS and the recorded Godot 4.7.2 binary:

```sh
python sketches/core-loop/tools/blender/dig_stone/stone_material.py
python sketches/core-loop/tools/blender/dig_stone/build.py --rerun-check
blender -b --factory-startup --threads 2 --python-exit-code 1 --python sketches/core-loop/tools/blender/dig_stone/preview.py
python sketches/core-loop/tools/blender/dig_stone/verify.py --previews
```

For one asset, run its same-basename recipe. `--out` supports a scratch destination:

```sh
blender -b --factory-startup --threads 2 --python-exit-code 1 --python sketches/core-loop/tools/blender/dig_stone/cut_face_long.py -- --out /tmp/cut_face_long.glb
```

`build.py` runs recipes serially with two threads, an 8 GiB address-space cap and a
180-second limit per export. It writes `assets/models/dig_stone/manifest.json` with
actual bounds, names, sockets, budgets, sizes and hashes. A separate temporary
rebuild must match every GLB byte. Recipes require no external art or git operation.

`preview.py` imports the exported GLBs. Cycles runs on CPU with two threads and
twelve samples. Each asset gets front, side and three-quarter views beside a
2 m ball. Results and hashes go under `artifacts/local/dress-preview/MDS/release/`.
The Blender material approximates the shared world-position beds using the same
eight thicknesses. These images are offline art evidence, not Godot renderer proof.

`verify.py` runs the named smoke test, retains raw Godot output and proves the same
test fails on separate scratch copies with a missing GLB and doubled geometry.
It gives Godot writable temporary config/cache/data paths. It removes only UIDs
generated by that invocation and moves its smoke receipt into the preview folder.
`--previews` also checks all twenty-four image hashes against their final GLB hashes.
The test checks actual imported vertices, triangles, draws, materials, names,
socket positions, metre bounds, origin, floor relief and the unplugged stone throat.

The single `stone.tres` embeds `target_bed4.gdshaderinc` verbatim from unmerged
revision `515f919`. That source is retained here for reproducibility. It uses the
existing sandstone and packed-sand textures as luminance detail, the D1 stone
palette, roughness 0.95 and the original eight-entry table. Each GLB carries a
neutral sandstone fallback and grayscale wear only. The wiring owner must assign
the shared material and align terrain parameters before claiming continuous beds.
Admitting this local copy does not merge or qualify that earlier branch.

The breach socket retains D1's 8x1x8 m surround and open 6 m throat, with nominal
surface Y=0 and stone extending to Y=-1. P-R6 changes the mechanical cover skin to
the existing 12x12 m and 14x10 m gameplay rectangles. This socket is an offline
study. The wiring owner must reconcile its support footprint before placement.
The landing socket is preview-only. The four beds are look studies and must never
be tiled into walkable islands. Bury the long cut face 0.25 m when placing it.

Automated checks and CPU previews do not establish native placement, collision
synchronization, camera clearance, performance or Andrew's visual acceptance.
